# 哈希与数据结构组使用范式

> **范围**：特殊数据结构组 6 个类（hash_comm / hash_map_mth / hash_vec / ring_hash / ring_window / smth_vec）的独立使用模式。全部 header-only，无 cpp。
> **边界**：本组独立。组合点见 §9（只点明不展开）。
> **源码基线**：include/hash_comm.h、hash_map_mth.h、hash_vec.h、ring_hash.h、ring_window.h、smth_vec.h

## 1. 组成员

| 类 | 角色 | 线程模型 | 内存 |
|---|---|---|---|
| `hash_str`/`hash_fm8<N>`/`hash_fm4<N>` | 哈希函数（表第 4 模板参数）| 无状态线程安全 | 无 |
| `hash_map_mth<N,K,V,HASH>` | 动态可扩展多线程哈希表（增量 rehash）| 多线程（读写锁+扩展互斥）| 自管理 new/delete |
| `hash_vec_pos<K,V,HASH>` + `vec_fix_mem<T>` | 固定内存哈希映射（占位索引）+ 对象数组 | 写互斥/读无锁 | **支持共享内存** |
| `ring_hash<D>` | 流序号取模哈希环 | 单线程 | 桶自管/节点外部池 |
| `ring_window<N,K,V,CMP>` + `ring_range_buf` | 有序环形窗口（大到小）+ 二级范围缓冲 | 单线程 | 自管理 |
| `smth_vec<T>` | 平滑扩展数组（POD）| 多线程（读写锁+扩展互斥）| 自管理 aligned_malloc |

## 2. 选型决策树

```
哈希表（key→value 检索）？
├─ 键数量波动大、动态扩展、多线程 → hash_map_mth（增量rehash+读写锁）
├─ 键数量启动固定、只增不删、需共享内存/跨进程 → hash_vec_pos + vec_fix_mem（写互斥读无锁）
└─ 键是整型递增流序号、单线程在途数据 → ring_hash（seq_no & mask 取模）

有序容器？
└─ 少量对象（几百）按 key 从大到小（如行情挡位）→ ring_window（单窗口）或 ring_range_buf（多窗口二级索引）

可扩展数组？
└─ POD 对象、多线程读写、自动扩容 → smth_vec（读写锁+SIMD扩容，索引=pre_no前缀+位置）
```

要点：`hash_map_mth`（动态+多线程通用）vs `hash_vec_pos`（固定+只增+共享内存）；`ring_hash`（流序号取模，适合 TCP seq 回绕）；`ring_window` 替代 STL map 用于几百个排序对象。

## 3. hash_comm 哈希函数（表的 HASH 模板参数）

三个 `static inline` 无状态函数，返回 `uint64`，末尾用黄金比例常数 `0x61C8864680B583EBull` 做斐波那契散列最终化：

| 函数 | 适用键 | 要求 |
|---|---|---|
| `hash_str` | 变长字符串（~32 字节）| `\0` 结尾 |
| `hash_fm8<N>` | 定长键，N 是 8 的倍数 ≤64 | `N%8==0`，8 字节步进 |
| `hash_fm4<N>` | 定长键，4 字节对齐 | 模板要求 N%8==0，实际 4 字节步进 |

用法：作为 `hash_map_mth`/`hash_vec_pos` 的 `HASH` 模板参数（传入函数类型，表内 `HASH()(key)` 调用）。

## 4. 单线程 vs 多线程接口

### 4.1 hash_vec_pos：insert（单线程）vs insert_mth（多线程）—— 不可混用

| 方法 | 查重 | 加锁 | 适用 |
|---|---|---|---|
| `insert(V&, const K&)` | 不查重直接追加 | 无锁 | 单线程，调用方保证 key 唯一 |
| `insert_mth(V&, const K&)` | 遍历链表查重 | `insert_lock` 自旋互斥 | 多线程 |

两者返回"占位索引"（从 1 编号），用于 `vec_fix_mem::get(pos)` 取内存。`insert_mth` 重复时返回已存在位置，不更新值。

### 4.2 hash_map_mth：find 的 need_lock 参数

```cpp
int32 find(V& o_val, const K& key, int32 need_lock=1);
```
- `need_lock=1`（默认）：内部读写锁，多线程安全
- `need_lock=0`：不加锁，**仅用于"先单线程构造好 map，之后只读无并发写"** 省锁

insert/erase 始终加写锁；扩展时 `exp_lock` 互斥，扩展期间释放 `data_lock` 让读继续（非对称锁）。

### 4.3 smth_vec：read（读锁）vs write（写锁+自动扩容）

- `read(T&, index)`：读锁，index 含 `pre_no` 前缀
- `write(T&)`：写锁，满则 `expand`（2 倍），扩展期间释放写锁再重获（其他写线程可能并发），`simd_copy` 复制旧数据
- `recover_reserve(tno, T&)`：SHM 崩溃恢复专用，不调 `save_no()`

## 5. POD 限制 + 2 的幂

| 结构 | POD | 2 的幂 |
|---|---|---|
| hash_map_mth | key/value 尽量 POD（大的存指针）| 篮子 2 的幂（扩展 2 倍）|
| hash_vec_pos / vec_fix_mem | key/value **必须 POD** | 篮子 2 的幂 |
| ring_hash | D 通常 POD | 桶数 2 的幂（`hash_mask=ts-1`）|
| ring_window | K/V 无强制（推荐存指针）| **N 必须 2 的幂**（`static_assert` 强制）|
| smth_vec | T **必须 POD 且实现 `save_no(int32)`** | 容量无强制，`expand` 最小 8 |

## 6. 共享内存支持

- **hash_vec_pos / vec_fix_mem**：`init(shm_name, ...)`，非空→`map_shm`（`is_create=1`创建/`0`打开），≥2MB 用大页。创建者初始化/故障恢复，打开者自旋等 `kv_num!=0`；`close(is_create)` 仅创建者释放
- **hash_map_mth**：不支持共享内存（new/delete 管理）
- **ring_hash**：桶数组可选外部内存（`init(it_num, pmem)`），但节点外部管理，无 SHM 协议
- **ring_window / smth_vec**：纯堆内存；smth_vec 有 `recover_reserve` 供外部 SHM 恢复

## 7. ring_window 有序窗口

- **N 必须 2 的幂**：`static_assert((N&(N-1))==0)` 强制；`mask=N-1` 位运算索引
- **排序方向**：从大到小（`CMP` 比较器，`cmp(a,b)>0` 表示 a 更优）。替代 STL map 用于几百个排序对象
- **insert_find 返回值**：`0`=未满新插入；`1`=覆盖插入（满且 key 比最小还小，弹出原最小）；`-1`=满且 key 最小未插入
- **二级结构**：`ring_window` 单窗口（固定数组+二分+移动保序）；`ring_range_buf` 多窗口二级索引（动态扩容，只增不减）
- `start_idx` 初始化 `N>>1`（中间），便于头尾双向增长

## 8. smth_vec 平滑扩展数组

- **POD + save_no**：T 必须 POD 且实现 `save_no(int32)`（write 时 `val.save_no(tu+pre_no)` 保存索引）
- **索引语义**：`索引 = pre_no 前缀 + 数组位置`；`pre_no>0` 时必须 `pre_no >= max_size`（前缀不与索引范围重叠）
- **动态扩展**：write 时满则释放写锁→`exp_lock` 互斥→`expand(2倍)`+`simd_copy`→重获写锁→写入；其他写线程检测 `ret==0` 重试
- **读不阻塞写**：read 读锁，扩展期间释放写锁，读可继续（COW 语义，旧块扩展完成才释放）

## 9. 迭代/遍历

| 容器 | 遍历支持 | 遍历方法 | 线程安全（遍历+并发写）| 限制 |
|---|---|---|---|---|
| hash_map_mth | 支持（弱一致）| `it_read_local` / `for_each` / `for_each_from` | 多线程遍历 OK；遍历+写弱一致；**遍历阻塞扩展** | 不建议常规遍历 |
| hash_vec_pos | 支持（顺序）| 外部 `for pos=1..size() { get(pos) }` | 读不加锁，并发写 OK（弱一致）| 只增不删 |
| ring_hash | 不暴露 | 无（basket 私有）| 非线程安全（单线程）| 非为遍历设计 |
| ring_window | 支持（有序）| `first_i/next_i/prev_i/last_i + get` | 非线程安全 | 无锁，须单线程或外部锁 |
| smth_vec | 支持（顺序）| 外部 `for i=pre_no..pre_no+size() { read(v,i) }` | rwlock 多读 OK；并发写弱一致 | POD + save_no |

**hash_map_mth 不建议遍历的原因**（关键）：
- 遍历持 `exp_lock` 读锁，**禁止 rehash 扩展**（扩展需写锁），遍历期间所有 insert 触发的扩展被阻塞，拖慢写吞吐
- 弱一致快照：begin 时固定 basket_count，但逐 basket 加读锁快照，basket 之间无锁覆盖，**会漏/重**（rehash 中途的 basket 遍历可能重复或遗漏）
- 大表遍历有拷贝开销（每 basket emplace_back K,V）
- 定位是"高并发查找/插入/删除的全局缓存池"，遍历是附带能力，适合低频运维/统计，**不适合业务热路径**

**hash_vec_pos 遍历**：按 `pos=1..kv_used` 顺序 `get(pos)`（pos 从 1）。读不加锁，并发写 OK（只增不删，不会读到已释放）。但 insert 先 `kv_used++` 后写 data 有窗口，遍历可能看到未写完槽位。

**ring_window 有序遍历**：`first_i`(最大 key) → `next_i`(更小) → ... → `last_i`(最小)，天然从大到小。`ring_range_buf` 多窗口跨窗口有序遍历（`start_i/next_i`）。非线程安全（无锁，insert/erase 会 move 数据）。

**smth_vec 顺序遍历**：`read(o_val, index)`，index 含 pre_no 前缀。rwlock 多读 OK，并发写弱一致（按起始 size() 走不越界，按动态 size() 走可能看到新写入）。

## 10. 与其他组的组合点（不展开）

- **哈希表存对象指针，对象由内存池管理**：`hash_map_mth<N,K,Obj*,HASH>` / `hash_vec_pos<K,int32,HASH>` 存索引或指针，对象由 `vec_fix_mem`/内存池组分配。hash_vec_pos + vec_fix_mem 标准联合（map 占位 → pos → 数组取内存）
- **ring_hash 配合缓存池**：`ring_hash_kv<D>` 节点从外部缓存池分配；`erase` 返回节点指针调用者归还
- **ring_window 存指针**：推荐 V 为对象指针，对象由内存池管理
- **锁依赖**：hash_map_mth/smth_vec 用 mlock 的 atomic_rwlock/rwlock/cmutex；hash_vec_pos 用 atomic_lock
- **SHM 依赖**：hash_vec_pos/vec_fix_mem 用 mutils 的 map_shm/unmap_shm

## 11. 避坑

1. **hash_map_mth 增量 rehash**：扩展后不一次性重哈希，**每次 insert 执行 7 步 rehash**（单双链表分裂）；扩展期间读不受影响但写性能波动。rehash 依赖篮子 2 的幂
2. **hash_vec_pos insert/insert_mth 不可混用**：insert 无锁不查重（单线程），insert_mth 加锁查重（多线程）。混用导致重复 key 或竞态
3. **hash_vec_pos 容量固定**：init 后不可扩展，满则 `LBERR_OBJ_IS_FULL`；只增不删
4. **ring_window N 必须 2 的幂**：static_assert 强制；数据应小（推荐存指针）；动态增长不缩小
5. **smth_vec POD + save_no**：T 必须 POD 且实现 save_no；扩展期间释放写锁，其他写线程可能并发
6. **smth_vec pre_no 约束**：`pre_no>0` 时必须 `pre_no >= max_size`，否则 init 失败
7. **hash_map_mth value 应小/存指针**：大的或非 POD 存指针
8. **ring_hash 不管理节点内存**：节点由外部缓存池分配，erase 返回节点指针调用者归还，close 只释放桶数组
9. **hash_vec_pos 共享内存恢复**：恢复逻辑只处理变长模式最后一个未完成写入，不处理"插入过程 core 导致内存丢失"
10. **hash_map_mth clear 保留结构**：clear 清数据但保留篮子内存，析构才 delete[]
