# 网络组使用范式

> **范围**：网络异步 IO 组（comm_sock / comm_aio / tcp_ch / udp_ch / heart_manage / reconnect_ctl / aio_recv_buf / aio_recv_pool / aio_recv_que / aio_tcp / aio_udp）的独立使用模式。
> **边界**：本组只讲网络类本身的使用。网络服务器组装（mthread+aio_tcp+que_mth_buf 跨组）属架构范式，此处只点明组合点不展开（§10）。
> **源码基线**：include/comm_sock.h、comm_aio.h、tcp_ch.h、udp_ch.h、aio_tcp.h、aio_udp.h、aio_recv_*.h、heart_manage.h、reconnect_ctl.h + src/tcp_ch.cpp

## 1. 选型决策树

### 1.1 协议层（comm_sock）
- `channel_attr.family` **仅支持 `CHANNEL_FAMILY_IPV4`(AF_INET)**；IPv6 已定义但未实现（tcp_ch.cpp 显式校验返回 `LBERR_ARGV_WRONG`）
- TCP → `tcp_ch`/`aio_tcp`；UDP → `udp_ch`/`aio_udp`（单播/组播/广播）

### 1.2 异步框架层 + 3 缓存策略
`aio_tcp<B,RC>` / `aio_udp<B,RC>` 模板，B/RC 由缓存类型决定：

| 缓存类 RC | 共享底座 | 预定义(tcp) | 预定义(udp) | 适用 |
|---|---|---|---|---|
| `aio_recv_buf` | 无（每通道 new[] 独占）| `tcp_buf_ch` | `udp_buf_ch` | 少量连接，最简单 |
| `aio_recv_pool<N>` | `fix_pool`（内存池组）| `tcp_mtu_pool_ch` | `udp_mtu_pool_ch` | 高并发多连接，共享池 |
| `aio_recv_que` | `que_swr_buf`（队列组）| `tcp_que_ch` | `udp_que_ch` | 多通道单线程消费，**非请求应答** |

**aio_recv_que 不适合请求应答**：共享队列消息与通道分离，无法把响应关联回正确连接（仅适合流式广播）。

## 2. aio_tcp 完整生命周期

**客户端**：`connect_ch(attr, &cb_msg, &cb_ch, precvth, &remote, &local?, asyn=0)` → `start_ch()` → `send_msg`/收 `deal_msg` → `close_ch(err)`
**服务端被接受**：`accept_ch(attr, &cb_msg, &cb_ch, precvth, fd)` → `start_ch()` → ... → `close_ch`
**监听端**：`tcp_listen_ch::listen_ch` + `start_listen(tplistenth)` → 回调 `deal_listen_accept(fd)` → 用户 new aio_tcp + `accept_ch(fd)`

### 三态返回值（connect_ch / create_tcp_connect_sock）
- `1` = 同步连接成功（已 `set_work` + 回调 `deal_ch_connect`）
- `0` = 异步进行中（epoll 等 EPOLLOUT；完成回调 `deal_ch_connect`；**异步失败走 `deal_after_closed`/`deal_ch_closed`，不走 `deal_ch_closing`**）
- `<0` = 失败（错误码）

`start_ch()` = `ch.start_poll_recv(th_recv, this)`，把 aio_tcp 自身作为 `epoll_event_op` 加入接收线程 epoll。poll 唤醒 → `deal_event` → `loop_deal_recv` → `deal_recv`（`buf.recv_msg` → `f_msg->deal_msg` → `buf.cmt_deal`）。

## 发送模式与线程安全

**send_msg 非线程安全**：`tcp_ch::send_msg`（tcp_ch.cpp L15-38）**无锁**，循环 `send(2)` 直到发完 len 字节。多线程并发 send 会导致两条消息字节流**交错拼接**（对端收乱序废包）。多线程发送必须外部串行化。

**4 种发送模式**（按推荐度）：

| 模式 | 做法 | send_msg 串行化保证 | 适用 |
|---|---|---|---|
| 1. 业务单线程直发 | 用户保证业务处理发送单线程，直接调 send_msg | 单线程天然串行 | 最简，deal_msg 回调内应答 |
| 2. 发送线程+私有队列（**推荐**）| 每线程/链接私有队列（如 link_send_que/que_swr_buf），用户发送入队，发送线程出队调 send_msg | 单发送线程消费队列串行 | 高并发；**发送线程可=接收线程** |
| 3. 事件封装投递（**推荐**）| 发送封装为 event_op，`delive_ch_event`/`delive_recv_event` 投递到接收/发送线程，线程 `deal_event` 时调 send_msg | deal_event 单线程串行 | 跨线程拉回接收线程；事件数据 ≤56 字节 |
| 4. 多线程+用户锁 | 用户多线程发，自行加 cmutex 保护 send_msg | cmutex 串行化 | 最差；EAGAIN 重试期间长持锁 |

**发送线程 = 接收线程模式**（模式 2/3 特例，对 onload 加速最优）：
- 发送队列由接收线程（th_recv）消费，或发送事件投递到 th_recv
- **关闭也汇聚接收线程**：`deal_ch_closing`/`deal_ch_closed` 经 aio_tcp_ch_op 回调在接收线程执行（close 由接收线程发起时）
- 链接的接收、发送、关闭全在接收线程单线程处理，**链接对象无需任何锁**
- **onload 加速意义**：单线程绑核 + 单 fd 不跨线程 epoll → OpenOnload 走最快路径（kernel-bypass/零拷贝/栈缓存命中）。fd 从 connect/accept 绑定一个接收线程 epoll，不跨线程迁移，onload 维持加速栈状态。若发送/关闭跨线程，onload 栈需跨核迁移上下文，加速下降

## 3. 回调基类（comm_aio.h / tcp_ch.h）

### ch_recv_cb<CH>
- `deal_msg(CH* pch, aio_msg& msg)` = **纯虚**，必须 override。返回 `>0`处理长度 / `=0`未处理（头/消息不完整）/ `<0`出错（底层丢弃本次并调 `deal_ch_error(AIO_CHERR_TYPE_DEAL)`）

### aio_ch_op<CH>（全部默认空实现，按需 override）
- `deal_ch_error(CH*, err_type, err_code)` — err_type: RECV/DEAL/SEND/EPOLL/LISTEN/CONNECT
- `deal_ch_closing(CH*, errcode)` — 首次关闭成功回调**一次**（在此让对象"不再可见"）
- `deal_recv_stop(CH*)` — 接收线程移除监听后通知
- `deal_ch_closed(CH*, errcode)` — 各线程结束使用，**在此释放对象资源**
- `deal_ch_connect(CH*, localaddr)` — accept/connect 建链成功

### tcp_listen_op（tcp_ch.h）
`deal_listen_accept(plistench, clientaddr, fd)`（返回<0底层自动关 fd）、`deal_listen_to_close`、`deal_listen_closed`、`deal_listen_error`。

> **用户只继承 `ch_recv_cb` + `aio_ch_op`**（+ `tcp_listen_op` 若监听），不直接碰底层 `tcp_ch_op`/`udp_ch_op`（aio_tcp 内部用 `aio_tcp_ch_op` 桥接翻译）。

## 4. 3 种缓存策略 + dispatch_zero_copy

三者 API 一致：`build_buf/init_buf` → `recv_msg` → `cmt_deal` → `cmt_buf/read_buf` → `reset_buf/close_buf`。

- **aio_recv_buf**（独立线性）：累积到 `curbuf`（单 buffer + recvlen + memmove 移除已处理）。`is_complete()` 恒 true。无共享
- **aio_recv_pool<N>**（共享 fix_pool）：`recv_msg` 写当前 take 的池块；`cmt_deal>0` 时立即 take 新块、memcpy 残留、换块（旧块靠 `cmt_buf` → `mpool->release(pos)` 释放）。支持外部共享池 `init_buf(attr, &share_pool)`
- **aio_recv_que**（共享 que_swr_buf）：`recv_msg` 首次 `write_get` 取写位；`cmt_deal>0` 调 `write_cmt` 提交，残留再 write_get + memmove。`is_complete()` 真判断 `recvlen==0`

**dispatch_zero_copy**（`aio_attr.dispatch_zero_copy=1`）：`deal_msg` 返回后缓存不立即回收，需分发线程处理完调 `dispatch_deal_end(buf_addr, deal_len)` 通知复用；**忘记调用 → 缓存泄漏**。

## 5. tcp_ch 引用计数（state_machine.h 的 src_stat_ref）

底座 `src_stat_ref thctl`：状态机 + 引用计数合一。
- `add_ref()`：仅 work 状态成功（计数+1），closing/closed 失败
- `sub_ref()`：计数-1，归零时**自动转 CLOSED** 返回 true
- `to_close(o_closed)`：转 CLOSING 阻止新 add_ref；引用已 0 则 `o_closed=true`
- 状态查询：`is_work()`(WORK且非CLOSING) / `is_close()`(≤CLOSING) / `is_free()`(==CLOSED)

### 配对规则
| add_ref 点 | 配对 sub_ref 点 |
|---|---|
| `delive_ch_event(..., needadd=1)` | `end_ch_event(1)`（事件处理完）|
| `start_poll_recv`（成功）| `end_poll_recv`（从 epoll 移除后，aio 层 `deal_close` 调）|
| `connect_ch` 内 `to_init`（隐含 ref=1）| 失败路径归零 / 正常关闭 sub_ref 归零 |

**needadd 语义**：`needadd=1` 投递时 add_ref，处理完必须 `end_ch_event(1)` sub_ref，否则引用泄漏导致对象永不 `deal_after_closed`；投递失败（队列满）底层已自动 sub_ref 回滚，**不要再 end**。`needadd=0` 不 add_ref，`end_ch_event(0)` 空操作。

### 关闭流程
```
close_ch(err)
  → thctl.to_close(closeflag)        // 转 CLOSING，阻止新引用
  → to_close 成功(首次): deal_closing → deal_tcp_to_close → aio 层 deal_ch_closing  // 首次一次
  → closeflag(引用已0): deal_after_closed → destroy()(close fd) → deal_tcp_closed → aio 层 deal_ch_closed  // 归零释放
```
- `deal_ch_closing`：底层保证**只调一次**但不保证线程。在此让对象"不再可见"
- `deal_ch_closed`：引用归零后调，**在此释放对象资源**。提前释放 → use-after-free

## 6. heart_manage 心跳

接口：`init(interval)` / `on_heart()` / `on_msg()` / `check_send()` / `check_timeout()`。
- `on_heart()`：更新 last_heart + **原子清零** msg_count
- `on_msg()`：`msg_count++` —— **非原子**，**必须在同一线程调用**（业务消息接收线程）
- `check_timeout()`：`return (tdiff >= interval*3) && (msg_count==0)`（3 倍间隔无心跳且无业务消息）。`interval=0` 禁用心跳
- `check_send()`：距 last_send ≥ interval 则更新 last_send 返回 true
- aio_tcp 暴露 `on_heart_msg/on_com_msg/check_heart_send/check_heart_timeout`，但 **`deal_recv` 内 `heart.on_msg()` 被注释**——**aio_tcp 不自动调 on_msg**，需用户在 `deal_msg` 回调里手动调 `on_com_msg()`/`on_heart_msg()`

## 7. reconnect_ctl 重连

状态三态：`DISCONNECTED(0)` / `CONNECTED(1)` / `NEED_CONNECT(2)`。
- `init(max_reconnect)`：0=无限重连
- `set_connected()`：清零 `m_reconnect_count`，置 `m_happen_connected=1`（仅在非已连接时生效）
- `set_disconnected()`：记录 `m_disconnect_time=now`，转 DISCONNECTED
- `check_reconnect(interval)` 三条件全满足返回 true：① `m_happen_connected==1`（**首次连接门**——从未成功连接过则不重连）；② 状态非 CONNECTED 且未超 max；③ 距 `m_disconnect_time ≥ interval`。返回 true 时**递增 count + 重置 m_disconnect_time=now**（作下次间隔起点）+ 转 NEED_CONNECT
- 间隔由外部传入，类内不保存。连续重连失败每次间隔固定（非指数退避）

## 8. udp_ch 特性

- `udp_ch::init_ch(attr, &cb, isrecv, ismulti, &remote, &local)`：单播/组播/广播
- **aio_udp::init_ch 强制 `oncerecvlen = maxmsglen`**：UDP 数据报一次收发完整，不可分片
- aio_udp 其余生命周期同 aio_tcp（init_ch→start_ch→send/deal→close_ch），但无 connect/accept

## 9. 避坑

1. **引用计数泄漏**：`delive_ch_event(needadd=1)` 必须配 `end_ch_event(1)`；`start_poll_recv` 成功后必须 `end_poll_recv`（aio 层 `deal_close` 调）。漏配 sub_ref → 对象永不释放
2. **on_msg 被注释**：aio_tcp/aio_udp 的 `deal_recv` 里 `heart.on_msg()` 是注释掉的。心跳的 on_msg/on_heart 须用户在 `deal_msg` 回调里**手动调** `on_com_msg()`/`on_heart_msg()`
3. **deal_ch_closed 才释放对象**：`deal_ch_closing` 只是"不再可见"，真正资源释放在 `deal_ch_closed`（引用归零后）。提前释放 → UAF
4. **仅 IPv4**：`channel_attr.family` 强制 AF_INET，IPv6 未实现
5. **aio_recv_que 非请求应答**：共享队列消息与通道分离，无法回填响应
6. **dispatch_zero_copy 泄漏**：=1 时必须调 `dispatch_deal_end`，否则缓存不回收
7. **异步连接失败不走 closing**：直接 `deal_after_closed`，用户在 `deal_ch_closed` 里要能处理"连接失败" errcode
8. **心跳 msg_count 非原子**：on_msg 不可跨线程（同线程约束）

## 10. 与其他组的组合点（不展开）

- **线程组**：`aio_tcp/aio_udp::start_ch()` 把自身（`epoll_event_op`）加入 `mthread` 的 epoll；`delive_ch_event`/`delive_recv_event` 向 mthread 投递事件。**网络服务器组装（mthread+aio_tcp+que_mth_buf）是跨组架构范式，本组不展开**
- **内存池组**：`aio_recv_pool<N>` 底座是 `fix_pool<aio_pool_item<N>>`，可外部共享 `init_buf(attr, &share_pool)`
- **队列组**：`aio_recv_que` 底座是 `que_swr_buf`，可外部共享 `init_buf(attr, &share_queue)`
