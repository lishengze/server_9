# 锁与同步组使用范式

> **范围**：并发同步组 5 个头文件（matomic / mlock / state_machine / wait_poll / wait_wake）的独立使用模式。
> **边界**：本组独立（matomic 是底层）。组合点见 §8（只点明不展开）。
> **源码基线**：include/matomic.h、mlock.h、state_machine.h、wait_poll.h、wait_wake.h + 对应 src

## 1. matomic：原子操作 + 内存屏障

### 1.1 五种屏障语义

| 宏 | 语义 | 典型用途 |
|---|---|---|
| `atomic_compiler_fence()` | 编译器屏障（无 CPU 指令）| 防变量缓存寄存器 |
| `atomic_read_fence()` | Acquire 读屏障（屏障后读写不重排到前）| 消费者读共享数据**之前** |
| `atomic_write_fence()` | Release 写屏障（屏障前读写不重排到后）| 生产者写共享数据**之后** |
| `atomic_memory_fence()` | Acq_Rel 通用屏障（双向）| 无锁数据结构核心操作 |
| `atomic_seq_fence()` | Seq_Cst 最强（全局总序）| 严格顺序保证，开销最大 |

### 1.2 原子操作矩阵

| 操作 | 16位 | 32位 | 64位 | 指针 |
|---|---|---|---|---|
| load（ACQUIRE）| load16 | load32 | load64 | load_ptr |
| store（RELEASE）| store16 | store32 | store64 | store_ptr |
| exchange（RELEASE）| exchange16 | exchange32 | exchange64 | exchange_ptr |
| cas 强 | cas16 | cas32 | cas64 | cas_ptr |
| cas 弱 | cas16_weak | cas32_weak | cas64_weak | cas_ptr_weak |
| fetch_add/sub（RELEASE）| fetch_add16/sub16 | fetch_add32/sub32 | fetch_add64/sub64 | — |

**Acquire/Release 约定**：load 全 ACQUIRE，store/exchange 全 RELEASE，CAS 成功 RELEASE/失败 ACQUIRE，fetch_add/sub RELEASE。

### 1.3 强 CAS vs 弱 CAS（关键选型）

| | 强 CAS | 弱 CAS |
|---|---|---|
| 虚假失败 | 不会 | 可能（值相等也返回 false）|
| 适用 | 非循环一次性 | **自旋循环**（性能优）|
| 铁律 | — | **必须包在循环里**且有退出条件 |

## 2. mlock：7 锁选型矩阵 + RAII 守卫

> **修正**：头注释提"rwlock_proc"但实际无此类，多进程读写锁是 `swlock_proc`。

| 锁 | 进程 | 互斥/读写 | 自旋/睡眠 | 底层 | 关键特性 |
|---|---|---|---|---|---|
| `atomic_lock` | 单 | 互斥 | 自旋 | CAS | POD；30000 自旋后 CPU_PAUSE；**不支持递归** |
| `atomic_rwlock` | 单 | 读写 | 自旋 | CAS 单 int32 | **写优先**（写等待阻塞新读）|
| `cspinlock` | 单 | 互斥 | 自旋 | pthread_spin | 构造即 init；PROCESS_PRIVATE |
| `cmutex` | 单 | 互斥 | 睡眠 | pthread_mutex | 临界区可较长；可配递归 |
| `rwlock` | 单 | 读写 | 睡眠 | pthread_rwlock | **写优先** |
| `cmutex_proc` | **多** | 互斥 | 睡眠 | pthread_mutex + SHARED + ROBUST | 必须放共享内存；EOWNERDEAD→consistent 恢复 |
| `swlock_proc` | **多** | 读写(写优先) | 睡眠 | sem_t 双信号量 | 必须放共享内存；`reinit()` 崩溃恢复；带超时 |
| `clock_guard<T>` | — | — | — | RAII 模板 | 构造 lock/析构 unlock；异常安全 |

### 多进程锁崩溃恢复
- **cmutex_proc**：`lock()` 检查返回码，`EOWNERDEAD` 调 `pthread_mutex_consistent` 恢复；不可恢复返回 `LBERR_LOCK_NOT_RECOVE`。`lock(o_badlock)` 重载输出 0=正常/1=修复/2=不可修复。robust 仅 `_POSIX_THREAD_ROBUST_MUTEXES` 定义时生效
- **swlock_proc**：`reinit()` 检测信号量异常值后 destroy+init 旁路恢复

### 写优先机制
atomic_rwlock 的 `write_lock` 两阶段：占写等待位（阻塞新读）→ 等读者清空后置写状态。防写饿死，但读极多时影响读者延迟。

## 3. state_machine：状态机（3 个类）

### 3.1 src_stat_ref —— 状态 + 引用计数合一

单 `int64 statref`：高位状态 + 低 48 位引用计数。状态转换：`CLOSED → INITING → INITED → WORK → CLOSING → CLOSED`

| 方法 | 转换 | ref | 返回 |
|---|---|---|---|
| `to_init()` | CLOSED→INITING | +1 | bool |
| `end_init(o_closed, ok)` | →INITED(成功)/→CLOSED(失败) | 不变 | bool |
| `set_work()` / `stop_work()` | INITED↔WORK | 不变 | bool |
| `add_ref()` | 仅 INITED/WORK 且非 CLOSING | +1 | bool |
| `sub_ref()` | ref-1，**ref归1且CLOSING→自动转CLOSED** | -1 | **true=资源需回收** |
| `to_close(o_closed)` | →CLOSING；ref==0 直接→CLOSED | 不变 | bool；o_closed=ref是否0 |

CAS 保证（关键点用强 cas64，循环用 weak）；`to_close` 后 `add_ref` 必失败（阻止新引用）。

### 3.2 src_async_ctl —— 异步事件投递控制

单 int64：ref + `CDELIVE_ASYNC_HAVE`(投递中) + `CDELIVE_ASYNC_CLOSE`。
- `to_async()`：CAS 置 HAVE +1，**最多一个异步事件在飞**
- `end_async()`：清 HAVE -1，返回 true=需执行关闭后操作
- 用途：网络读队列事件/定时器事件/资源回收保护，减少重复投递

### 3.3 spin_state_lock —— 自旋状态锁

单 `int32 state_`：低 16 位主状态（IDLE→INITING→WORKING→CLOSING→IDLE）+ 高 16 位附加操作（SEND/RECV）。
- `to_init/end_init`：CAS 保证唯一线程进入
- `send_lock()`：**发送优先**——占 SEND 位后等 RECV 清空且 WORKING
- `recv_lock()`：先等 SEND 清空再占 RECV
- `to_close()`：CAS WORKING→CLOSING，保留附加位等收发清空
- **适用**：POD 可入共享内存；**临界区必须极短**，禁止持锁做 IO；网络收发状态机（tcp_ch 收发互斥）

## 4. wait_poll：epoll 封装

### 4.1 epoll_event_op 回调基类
虚接口：`deal_event()`/`deal_error()`/`deal_close()`/`get_fd()` + `set_event(outflag, edgeflag, load_cnt)`。子类（aio_tcp 等）继承挂入 epoll。

### 4.2 wait_poll_one（单事件）
单 epoll fd + 单事件，`int32 isremove` 5 态状态机（0空闲/1添加中/2工作/3待删除/4删除中）管理生命周期。`add_wake/mode_wake/remove_wake(延迟)/delete_wake(立即)/wait`。

### 4.3 wait_poll_multi（多事件）
内置 `event_wake change_event`（变更通知）+ `atomic_lock dellock`（删除保护）。
- `add_wake`：直接 `epoll_ctl ADD`（EEXIST 容忍）
- `remove_wake`：**延迟删除**——追加到 del_evs + change_event.wake 唤醒，下次 wait 时 del_wake 真删
- `delete_wake`：立即 `epoll_ctl DEL`
- **延迟删除期间 fd 仍可能就绪触发 deal_event**——子类需容忍"已标记删除但仍收事件"

## 5. wait_wake：eventfd 封装（event_wake）

单 `int32 ev_fd`。`init(need_multicast)`：
- **信号量模式** `init(1)`（EFD_SEMAPHORE）：wake N 次需 reset N 次清空（每次 read 减 1）。适合**队列唤醒**（逐项唤醒）
- **计数器模式** `init(0)`：reset 一次 read 出累计值全清。适合**单次通知**（如退出信号）

`wake(ctl=1)` / `reset()` / `get_fd()` / `destroy()`。

## 6. 命名约定

- `clock_guard<T>`：RAII 守卫，T 需 lock/unlock
- 锁统一 `init()/lock()/unlock()`；读写锁 `read_lock/read_unlock/write_lock/write_unlock`
- 多进程锁额外 `destroy()` + 返回错误码（非 assert）
- 状态机 `to_xxx/end_xxx/set_xxx`
- 轮询器 `add_wake/mode_wake/remove_wake/delete_wake/wait`
- 屏障宏全小写 `atomic_xxx_fence()`
- 自旋阈值 `SPIN_LOCK_BUSY_COUNT 30000`

## 7. 避坑

1. **原子 ≠ 线程安全**：单变量原子，多变量组合仍需锁或屏障。写端 `atomic_write_fence` + 读端 `atomic_read_fence` 必须配对
2. **CAS 强弱选择**：循环用 weak（state_machine 全用 weak 在 while 内），非循环用强。弱 CAS 循环必须有退出条件
3. **atomic_lock 死锁**：不支持递归，同线程二次 lock 死锁；自旋不 yield
4. **多锁顺序防死锁**：多锁场景需全局统一加锁顺序（源码未强制，调用方自律）
5. **写优先防写饿死**：atomic_rwlock/rwlock/swlock_proc 均写优先，写等待阻塞新读。读极多时影响读者延迟
6. **自旋锁 CPU**：atomic_lock/atomic_rwlock/spin_state_lock 持有期间满自旋，**临界区必须极短**；长临界区用 cmutex/rwlock（睡眠）
7. **多进程锁崩溃恢复**：cmutex_proc 的 lock 必须检查返回码（EOWNERDEAD→consistent）；swlock_proc 用 reinit() 旁路恢复。**初始化进程 core 后锁不一定可用**
8. **state_machine 引用计数必须配对**：to_init/add_ref 的 +1 必须有 sub_ref 的 -1；sub_ref 返回 true=最后一个引用+已 to_close→自动转 CLOSED，调用方需回收资源
9. **wait_poll_multi 延迟删除**：remove_wake 是延迟删除，期间 fd 仍可能触发 deal_event，子类需容忍
10. **eventfd 模式选择**：信号量模式 reset 一次消一个唤醒，计数器模式 reset 一次清空。用错会丢唤醒或多余唤醒
11. **cmutex_proc robust 条件编译**：仅 `_POSIX_THREAD_ROBUST_MUTEXES` 定义时生效，否则退化为普通进程间互斥锁，崩溃恢复不可用
12. **fetch_add64 参数类型**：add_val 是 `int32`（非 int64），跨类型传参注意

## 8. 与其他组的组合点（不展开）

- **mlock 保护容器**：atomic_lock/cmutex 常保护 vector/hash_map 并发访问（如 wait_poll_multi 内 dellock 保护 del_evs）
- **wait_poll 被 mthread 用**：线程组事件循环基于 wait_poll_multi::wait() 驱动
- **state_machine 被 tcp_ch 用**：网络组用 src_stat_ref 管理连接引用计数、spin_state_lock 管理收发互斥（本组讲 state_machine 本身用法）
- **wait_wake 被队列用**：event_wake 作队列唤醒原语，配合 wait_poll 实现"队列有数据→唤醒 epoll→线程处理"
- **matomic 是底层**：mlock/state_machine/wait_poll 全部依赖 matomic 的 CAS/load/store 实现无锁路径
