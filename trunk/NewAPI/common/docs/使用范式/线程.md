# 线程组使用范式

> **范围**：异步事件与线程组（mevent / simple_thread / mthread / mthread_pool / time_thread / timer_order_list / thread_comm）的独立使用模式。
> **边界**：线程组独立（自带 pthread 循环 + epoll 骨架）。组合点见 §9（只点明不展开）。
> **源码基线**：include/mevent.h、simple_thread.h、mthread.h、time_event.h、time_thread.h、thread_comm.h + 对应 src

## 1. 选型决策树

```
需要定时器？
├─ 是 → timer_thread（timerfd+epoll，后台线程自动跑）
│       （底层 timer_order_list 是纯数据结构无线程，timer_thread 内部已持有）
└─ 否 → 需要线程？
    ├─ 单任务循环 → simple_thread（继承 do_work/need_work）
    │   ├─ CPU 密集/快响应 → 忙轮询（busyround>0）
    │   └─ I/O 密集/省 CPU → 等待触发（pollms>0，eventfd 唤醒）
    ├─ 事件队列驱动（多生产者投递，单线程消费）→ mthread（epoll + que_mth_fixed<event_info>）
    │   ├─ 省 CPU → waitms>0（epoll 阻塞）
    │   └─ 极限吞吐 → waitms<=0 且 eventq_size>=32（纯忙轮询）
    ├─ 多事件线程按负载/CPU 分配 → mthread_pool（持 N 个 mthread）
    └─ 裸 pthread（不要循环框架）→ thread_comm::run_thread / wait_thread
```

要点：要定时器线程用 `timer_thread`；只在别的线程里想要定时器数据结构时才直接用 `timer_order_list`。`simple_thread` 适合"一线程干一件事的循环"；`mthread` 适合"多线程投递事件、单线程消费队列"。

## 2. simple_thread 两种模式

`init_th(busyround, cpuid, pollms)`：`busyround==0` → 忙轮询（runmod=1）；`busyround>0` → 等待触发（runmod=2，`loopround=max(busyround,10)`，`pollwaitms=pollms`）。两者互斥。

### 2.1 忙轮询（busy_run）
```
while (state==2 && g_signal_stopctl==-1) do_work();   // 死循环不停
```
无等待无唤醒，CPU 拉满。`need_work()` 在此模式**不被调用**。

### 2.2 等待触发（busy_wait_run）
```
while (state==2 && g_signal_stopctl==-1) {
  epoll_wait(epollfd, &epevent, 1, pollwaitms);   // 阻塞 pollms
  if (waitret>0) read(evtfd, &event_data, 8);     // 清 eventfd
  for (curround=0; curround<loopround; curround++) do_work();  // 跑 loopround 轮
  if (need_work()) { write(evtfd, 1); }           // 还有活，自唤醒
}
```
- `trigger()`：仅 `waitflag==1`（线程真在等）时 `write(evtfd,1)`；线程工作中调无副作用
- `do_work()`：**纯虚必须 override**；`need_work()` 默认 FALSE，子类按需 override（返回 true 触发自唤醒继续跑）
- `loopround`：每次唤醒连续执行 do_work 轮数（批处理，减少 eventfd 往返）

## 3. mthread 事件队列模型

### 3.1 数据成员
- `wait_poll_multi waitpoll`（epoll 轮询器，可挂多 fd）
- `que_mth_fixed<event_info> eventq`（事件队列，队列组）
- `int32 waitms`（决定 epoll vs 忙轮询）
- `int32 eventq_busy_num`（每轮处理事件数，默认 6）
- `event_wake que_wake`（队列唤醒器，通知 epoll 队列有新事件）
- `int32 load`（原子负载计数，供 pool 选线程）

### 3.2 投递事件（生产者，多线程安全）
两条路径本质都是写 `eventq`：
- **直接写**（推荐）：`eventq.write_mth(ev)`（CAS 抢位+写+`write_cmt_mth`，返回 0=满）
- **reserve 风格**：`get_event(pe, pos)` → 填 `pe->buf` → `cmt_event(pos)`（当 `waitms>0 && eventq.get_used()<4` 时调 `que_wake.wake()` 唤醒 epoll）

### 3.3 消费事件（线程侧，单线程）
`deal_queue()`：循环 `eventq_busy_num` 次：`read_get(pe)` → `pe->op->deal(pe->buf)` → `read_cmt(1)`（必须提交，否则队列不前进）→ 全空返回 true。

### 3.4 模式判定（_f_mthread_func）
- `waitms>0 || eventq_size<32` → **epoll 模式**：`waitpoll.wait(waitms)` 阻塞；事件源 = eventq（经 que_wake 触发）+ `add_poll_event` 进来的 fd（网络组合点）
- `waitms<=0 且 eventq_size>=32` → **纯忙轮询**：死循环 `deal_queue()`，不进 epoll，纯靠队列轮询（极高吞吐但 CPU 拉满）
- `waitms<0` 钳到 100

## 4. mthread_pool 负载均衡

### 4.1 assign_thread(o_thread, exid, isround=0)
- `isround!=0`（轮询）：取第一个 running 线程，`lastassign=i+1`
- `isround==0`（默认，负载最小）：扫一圈取 `atomic_load(&load)` 最小的 running 线程
- `exid` 排除指定线程
- **一定成功**（无 running 时 fallback 返回 ths[0]，但调用方应 `is_running()` 自查）

### 4.2 assign_by_cpu(o_thread, cpuid)
线性找 `cpuid` 匹配的线程；找不到走轮询兜底。**可能亲和未命中**。

### 4.3 绑核
`init_set_cpu(tcpuid)` 仅记录；真正绑在 `run()` 里用 `pthread_attr_setaffinity_np` + **SCHED_RR 最高优先级**（需 root/CAP_SYS_NICE）。

## 5. timer_thread / timer_order_list 定时器

### 5.1 timer_thread（timerfd+epoll 线程）
- `init()`：建 `wait_poll_one` + timerfd（`CLOCK_MONOTONIC` 非阻塞，挂 epoll）
- `run()`：起 pthread 跑 `deal()`（`while(state==2) epollfd.wait(100)`）
- `add_timer(ev)`：`list.add_timer` → `list.get_interval()` 取最近超时 → `timerfd_settime` 重设 → `epollfd.mode_wake()` 唤醒
- 超时链：timerfd 可读 → `deal_event` → `list.loop_timer(tinterval)` 遍历到期定时器 → 重设 timerfd
- `it_interval` 保底 30ms，实际到期由 `it_value` 驱动

### 5.2 timer_order_list（有序链表，纯数据结构）
- `TIMER_MIN_UNIT_US=10`（最小粒度，`timer<10` 钳到 10）
- `add_list`：按 `outtime=begintime+timer` 有序插入，**O(n) 遍历**（几百个可接受，上千考虑分层时间轮）
- `loop_timer`：取链头，`tm>=outtime` 出队回调 `op->deal_timer(isperiod, timer, buf)`；`isperiod==0` 删除，否则 `add_list` 重新插入（周期续期）
- 并发：`atomic_lock mlock` 保护；timer_thread 单线程消费，多线程可 add/delete

### 5.3 time_event_info
`op`(time_event_op*) + `isperiod`(0单次/1周期) + `timer`(微秒间隔) + `buf[48]`(POD 数据)。回调 `deal_timer(is_period, timer, pbuf)`。

## 6. 生命周期（统一）

| 阶段 | simple_thread | mthread | timer_thread | mthread_pool |
|---|---|---|---|---|
| init | `init_th(busyround,cpuid,pollms)` | `init_th(id,maxpoll,eventq_size,eventq_loop,waitms)` | `init()` | `init(N,maxpoll,eventq_size,eventq_busy,waitms)` |
| 启动 | `run()` | `run()` | `run()` | `run()` 启动全部 |
| 停止 | `to_stop()` 设 state=3 | `to_stop()` CAS 置 ToStop | `to_stop()` CAS 2→3 | `to_stop()` 逐个停 |
| 等待 | `join()`(自动 to_stop) | `join()`(自动 to_stop+pthread_join) | `join()`(自动 to_stop) | `destroy()`(逐个 join+delete[]) |

**关键：析构都不自动停止运行中线程**（simple_thread/mthread/timer_thread 析构只关 fd/清资源）。必须显式 `to_stop()+join()`（或 pool 的 `destroy()`），否则 pthread 句柄泄漏 + use-after-free。

**全局停止**：所有线程循环都查 `state` 和全局 `g_signal_stopctl`（初值 -1）。`install_signal_hand` 把 SIGTERM/SIGQUIT 设为停止处理，收到信号置 `g_signal_stopctl=信号号`，所有线程循环退出——进程级优雅停止总开关，主线程应早调。

## 7. 回调基类（mevent.h）

- `event_op`：纯虚 `void deal(char* pbuf)`。投递时填进 `event_info{op, buf[56]}`，mthread 消费时 `pe->op->deal(pe->buf)`。**buf 必须 POD**（memcpy 传递，定长）
- `time_event_op`：纯虚 `void deal_timer(int32 is_period, int32 timer, char* pbuf)`
- `epoll_event_op`（wait_poll.h）：epoll fd 事件回调基类（`deal_event/deal_error/deal_close/get_fd` + `set_event`），mthread 私有继承、timer_thread 公有继承——把 fd 事件接入 epoll

## 8. 避坑

1. **simple_thread volatile 非原子**：`state`/`waitflag` 是 `volatile int32`，`to_stop()` 直接 `state=3`（非 CAS），`trigger()` 读 `waitflag` 非原子。高竞争无内存序保证，不要当高并发原语。mthread/timer_thread 的 state 才是 `atomic_cas32`
2. **mthread 析构不自动停**：`~mthread(){ destroy(); }` 只清资源不 join。运行中析构=泄漏+UAF。必须先 `to_stop()+join()`。timer_thread 同理
3. **cmt_event / read_cmt 必须调**：reserve 风格 `get_event` 后必须 `cmt_event(pos)`；`deal_queue` 每处理一个 `read_cmt(1)`。漏调 → 队列位不前进 → 卡死。直接 `write_mth` 路径内部已含提交
4. **timer 精度有限**：最小 10us 是数据结构粒度；实际受 timerfd + epoll wait(100ms) + 调度制约，非硬实时
5. **timer 插入 O(n)**：几百个可接受，上千考虑分层时间轮
6. **simple_thread 两模式互斥**：`busyround==0` 二选一；等待触发下 `loopround<10` 抬到 10
7. **mthread 模式分支**：`waitms>0 || eventq_size<32` 走 epoll，否则纯忙轮询。省 CPU 必须 `waitms>0`
8. **绑核需权限**：`run()` 绑核同时设 SCHED_RR 最高优先级，非 root 失败返回 `LBERR_ATTR_SET_FAIL`
9. **assign_thread 一定成功但可能无 running**：fallback 返回 ths[0]，投递前最好 `is_running()` 自查
10. **g_signal_stopctl 全局停止**：`install_signal_hand` 是进程级优雅退出总开关，主线程应早调

## 9. 与其他组的组合点（不展开）

线程组独立（自带 pthread 循环 + epoll 骨架）。组合点是"把别的组对象挂进 mthread 的 epoll"或"用队列组类型当事件载体"：

| 组合点 | 在哪 | 怎么组合 | 不展开 |
|---|---|---|---|
| **队列组** | mthread 的 `eventq` | `que_mth_fixed<event_info>` 作事件载体；生产者 `write_mth`/`get_event+cmt_event`，消费者 `read_get+read_cmt` | que_mth_fixed 并发语义、容量 |
| **网络组** | mthread 的 `add_poll_event` | 任意 `epoll_event_op` 子类（aio_tcp/aio_udp 连接）挂进 mthread 的 `waitpoll`，连接事件由该线程驱动；`load` 随之增减 | aio_tcp 连接管理、读写流程 |
| **定时器** | timer_thread 内含 timer_order_list | timer_thread 是"线程+timerfd"壳，委托 timer_order_list；也可单独用 timer_order_list 挂自定义线程 | （同组已展开）|

**边界一句话**：线程组提供"线程循环 + epoll 骨架 + 定时器壳"；队列组提供"无锁定长队列"作事件载体；网络组提供"epoll_event_op 子类"作 fd 事件源。三者通过 `epoll_event_op` 接口和 `que_mth_fixed` 模板组合，互不耦合内部实现。
