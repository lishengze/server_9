# 内存池组使用范式

> **范围**：内存池组（fix_pool / dync_pool / dync_pool_c1h / shm_block_pool / shmem_block_c1h）的独立使用模式。
> **边界**：内存池组独立，不依赖队列/线程。组合点见 §8（只点明不展开）。
> **源码基线**：include/fix_pool.h、dync_pool.h、shmem_pool.h + src/shmem_pool.cpp

## 1. 组结构

| 组件 | 头文件 | 实现 | 角色 |
|---|---|---|---|
| `fix_pool<T>` | fix_pool.h | 头文件内联 | 固定容量池，空闲链表 |
| `dync_pool<N,T>` | dync_pool.h | 头文件内联 | 动态扩展主级（管块链表）|
| `dync_pool_block<N,T>` | dync_pool.h | 头文件内联 | 块（N 个对象，子级单元）|
| `dync_pool_c1h<N,T>` | dync_pool.h | 头文件内联 | 线程私有块缓存句柄 |
| `shm_block_pool` | shmem_pool.h + .cpp | .cpp | 共享内存主级（area→block）|
| `shmem_block_c1h<D>` | shmem_pool.h | 头文件内联 | 单数据类型私有缓存句柄 |

辅助：`shm_data_addr`(area_id/block_id/data_id 三级寻址)、`shm_addr_unit`(与 int64 pos 联合，可原子跨进程传递)、`shmem_pool_recover`(恢复回调接口)。

## 2. 选型决策树

按「容量特征 × 跨进程 × 线程模型」三维：

```
跨进程共享？
├─ 是 → shm_block_pool + shmem_block_c1h<D>
│        （共享内存，三级寻址 area→block→data，仅单进程写）
└─ 否 → 容量固定可预估？
         ├─ 固定 → fix_pool<T>（init(tnum) 一次定容，不扩展，最轻量）
         └─ 动态增减 → dync_pool<N,T> + dync_pool_c1h<N,T>
                      （主级动态扩展块，子级线程私有缓存）
```

线程模型选配（三类池统一）：
- **单线程**：`get` / `back`
- **多线程**：`take` / `release`（内部 atomic_lock/mlock 自旋锁）
- **私有缓存句柄 c1h**：`init(pool, pool_is_mth)`，`pool_is_mth` 决定向主级请求走 `get` 还是 `take`；c1h 自身再提供单/多线程两套接口

## 3. get/back 配对规则

### 3.1 命名约定（三池统一）

| 线程模型 | 获取 | 释放 |
|---|---|---|
| 单线程 | `get` | `back` |
| 多线程 | `take` | `release` |

### 3.2 重复释放检查的不对称性（关键避坑）

- `fix_pool::release(int32 get_pos)` **有**重复释放检查：判 `tp->next_free != -2`（`-2`=已分配）才归还
- `fix_pool::release(T* get_buf)` **没有**重复释放检查：直接 `data2it` 反算挂回
- `fix_pool::back`（单线程，两重载）**均无**检查
- `dync_pool`/`dync_pool_c1h`/`shmem_block_c1h` 的 release **均无**重复释放检查（按指针/地址直接挂回）

**含义**：多线程下要享受重复释放保护，必须用 `release(pos)` 而非 `release(buf)`；用指针释放调用方自负其责。单线程 `back` 完全无保护，重复释放立即错乱。

空闲链表语义：`next_free==-1` 链表末尾，`==-2` 已分配不在空闲表。

## 4. dync_pool 两级管理 + c1h 线程私有缓存

### 4.1 两级架构

- **主级 `dync_pool`**：维护 `all_list`（所有块，close 时遍历释放）+ `first`（空闲块链表，供 get/take）
  - `init(init_block_num, is_keep_mem, expand_block_num=4)`：预分配初始块；`keep_mem=1` 时归还块永不释放回系统
  - `get/take(block)` 取块，`back/release(block)` 归还；`free_num < init_num || keep_mem==1` 时挂回空闲链表，否则 `free_blk` 真正释放
- **子级 `dync_pool_block<N,T>`**：块内 N 个对象，`free_pos[]` 数组管理空闲位（栈式），`first_free` 游标

### 4.2 线程私有缓存 `dync_pool_c1h<N,T>`

每线程一个，持 `head` 私有空闲块链表：
- `get/take(o_buf)`：先扫私有链表取对象；私有块耗尽则向主级 `pool->get/take` 要新块挂头
- `back/release(buf, pos)`：归还到所属块；**块全空闲（`free_num()==N`）时返还主级**；**块从空变非空（`free_num()==1`）时挂入私有链表**
- `pos2blk(pd, pos)`：用 `offsetof(datas)` + `pd-pos` 反算块地址——**这是 POD 限制的根源**

**归还条件**：块所有对象空闲 → 返还主级；块首次变非空 → 进入私有链表。c1h 天然按线程私有，一线程一个，减少主级锁竞争。

## 5. shmem_pool 共享内存语义

### 5.1 创建者 vs 打开者

- `init(..., create_mem)`：`create_mem!=0` → `is_write=1`（创建者）；`==0` → `is_write=0`（打开者）
- 打开者 `alloc_area`：`assert(1==shmisexist)` 且**自旋等 `ta->state!=0`**（创建者 init_area 完成置 1）

### 5.2 recover / rebuild / close 仅创建者

- `recover(pfunc)`：`is_write==0` 直接 return；创建者遍历块调 `pfunc->recover_data` 重建空闲链表。**读进程不应调 recover**（依据数据恢复，不依据内存）
- `rebuild()`：`is_write==0` 仅补映射缺失 area；创建者才 `init_area` 重置
- `close()`：`is_write==0` 直接 return；创建者置 `state=0` 清理

### 5.3 三级寻址 shm_data_addr

`area_id`(int16) + `block_id`(int32) + `data_id`(int16)，`alignas(8)`，与 `int64 pos` 组成 `shm_addr_unit` 联合体（可原子读写跨进程传递）。跨进程寻址：`addr2area → addr2block → addr2data`，各进程 `area_mems[area_id]` 映射同一共享内存名 `"<prev_name>_area_<id>"`。跨进程拿 `shm_data_addr` 即可定位同一对象。

## 6. POD 限制（强制）

三个池都要求对象为 **POD**（无虚函数/无复杂构造析构），根因是固定偏移反算：
- `fix_pool::data2it(T* pd)`：用 `&(null_ptr->data)` 编译期偏移 `toff`，`pd - toff` 反算 `fix_pool_it<T>*`。T 有 vtable → `data` 前有 vptr → 偏移错位
- `dync_pool_c1h::pos2blk`：`offsetof(m_blk, datas)` + `pd - pos` 反算块地址，同样依赖 `datas` 内 T 无隐藏成员
- `shmem_pool`：共享内存跨进程不调构造/析构

dync_pool 头注未写 POD，但 `pos2blk` 同样依赖固定偏移，**实际同样要求 POD**。

## 7. 模板参数 N（dync_pool `<int8 N, T>`）

- N 类型 `int8`，块内位置索引 `free_pos[N]`、`first_free` 均 int8
- **N 建议 `8*n - 2`**（如 62=8*8-2, 126=8*16-2）
- 上限 **126**（int8 有符号，留负值空间给失败标记 `(int8)LBERR_OBJ_IS_EMPTY`）
- `-2` 为对齐/SIMD 留余（块用 `aligned_malloc(ts, SIMD_ALIGN_SIZE)`）

## 8. 与其他组的组合点（不展开）

内存池组独立，职责是对象/数据分配回收。组合点：
- **+ 队列**：队列投递内存池分配的对象（常投递 `shm_data_addr` 或对象指针/pos），消费者从队列取出后到池 `addr2data`/`pos2buf` 取对象。组合点在"队列载荷=池对象句柄"
- **+ 线程**：线程从池 `take` 对象加工再 `release`；c1h 句柄天然按线程私有，一线程一个
- **+ 网络（实证）**：`aio_recv_pool<N>` 底座是 `fix_pool<aio_pool_item<N>>`（typedef `aio_mtu_pool`），多线程路径用 `take/release(pos)`，支持外部共享内存 `init(buf, size, 0)`

## 9. 避坑

1. **POD 限制**：三池都要求 POD，根因 `data2it`/`pos2blk` 固定偏移反算，有 vtable 错位
2. **重复释放**：多线程用 `release(pos)` 才有保护（fix_pool 检查 `next_free!=-2`）；`release(buf)` 无保护；单线程 `back` 完全无保护
3. **初始化单线程**：三池 init 尽量单线程（fix_pool `init_mem` 建/恢复空闲链表、dync_pool `init` 建 all_list、shmem `init_area` 建块链表），并发 init 损坏链表
4. **共享内存只读原则**：shmem_pool **仅单进程写**（get/take/back/release），其他进程只按 `shm_data_addr` 读
5. **get/back vs take/release 不可混用**：单线程无锁、多线程加锁，混用损坏
6. **fix_pool 外部内存恢复**：`init(pshm, mem_size, is_recove)`，`is_recove=1` 遍历节点按 `next_free==-2` 重建空闲链表；恢复期间无并发
7. **dync_pool keep_mem**：`=1` 归还块永不释放（避免 malloc/free 抖动）；`=0` 且 `free_num>=init_num` 时真正释放
8. **shmem 读进程不等创建者即访问**：打开者自旋等 `state==1`，创建者必须先启动
