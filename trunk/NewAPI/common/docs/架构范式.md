## 范式 1：网络服务器组装（mthread + aio_tcp + que_mth_buf）

**场景**：基于 epoll 的高性能异步 TCP 服务器，接收线程收消息、业务线程发消息、定时器线程管心跳重连。

**组装的使用范式**：
- 线程（mthread/mthread_pool）→ 线程.md §3（事件队列模型）
- 网络（aio_tcp/tcp_ch）→ 网络.md §2（生命周期）+ §5（引用计数）
- 队列（que_mth_buf）→ 队列.md §3（write/read 配对）

**组装要点**（各使用范式的衔接，不重复定义对方用法）：
1. `mthread_pool::init → run`（线程范式）
2. `aio_tcp::connect_ch/accept_ch → start_ch`（网络范式）—— `start_ch` 把 aio_tcp 加入 mthread 的 epoll（线程范式的 `add_poll_event` 组合点）
3. aio_tcp 回调（`deal_msg`/`deal_ch_*`）在 mthread 接收线程触发（网络范式 §3 回调线程）
4. 跨线程分发用 `que_mth_buf`（队列范式）+ `delive_ch_event(needadd=1)`/`end_ch_event(1)` 引用计数配对（网络范式 §5）
5. 发送：`send_msg` **非线程安全**，多线程发送须外部串行化——4 种发送模式见网络.md §发送模式（推荐发送线程+私有队列，发送线程可=接收线程，关闭也汇聚接收线程，对 onload 加速最优）
6. 关闭：`close_ch → deal_ch_closing`(首次) `→ deal_ch_closed`(引用归零释放)（网络范式 §5）

**关键衔接约束**（组装时易错，详见各使用范式）：
- `start_ch` 必须在 `deal_ch_connect` 之后（网络范式 §2）
- `delive_ch_event(needadd=1)` 必须配 `end_ch_event(1)`，否则引用泄漏（网络范式 §5）
- `deal_ch_closed` 才释放对象（网络范式 §5）
- 回调线程：`deal_msg` 在接收线程，`deal_ch_closed` 在最后 sub_ref 的线程（网络范式 §3）

## 范式 2：跨进程共享组装（shmem_pool + que_proc_buf）

**场景**：进程间共享内存通信，单进程写、其他进程只读。

**组装的使用范式**：
- 内存池（shmem_pool/shm_block_pool）→ 内存池.md §5（共享内存语义）
- 队列（que_proc_buf）→ 队列.md §4（跨进程语义 + op_pid 崩溃检测）

**组装要点**：
1. 创建者：`shm_block_pool::init(create_mem=1)`（内存池范式 §5.1）+ `que_proc_buf::init(is_create=1)`（队列范式 §4.1）
2. 写：`shm_block_pool::take_block → take_data` → 通过 `que_proc_buf::write_mp` 投递 `shm_data_addr`（队列范式 §4.2）
3. 打开者：`shm_block_pool::init(create_mem=0)`（自旋等 `state==1`）+ `que_proc_buf::init(is_create=0)`（自旋等 `mask!=0`）
4. 读：通过 `shm_data_addr` + `area_mems` 直接读（内存池范式 §5.3，**不调 get/release**）
5. close：创建者 `close(1)` 释放，打开者 `close(0)`（两范式一致）

**关键衔接约束**：
- 启动顺序：创建者必须先 init（两范式都自旋等）
- 写进程必须是创建者（队列范式 §4.1）
- `shm_block_pool` 仅单进程写，其他只读 `shm_data_addr`（内存池范式 §5）
- `que_proc_buf` 崩溃恢复丢数据（队列范式 §4.2），业务须容忍
- close 的 `is_create` 参数必须正确（两范式一致）

## 范式 3：重连心跳组装（reconnect_ctl + heart_manage + aio_tcp）

**场景**：维持长连接活性——定时器线程查心跳超时/重连，接收线程收消息/处理连接事件。

**组装的使用范式**：
- 网络（aio_tcp + heart_manage + reconnect_ctl）→ 网络.md §6（心跳）+ §7（重连）+ §2（生命周期）
- 线程（定时器）→ 线程.md（timer_thread 或 mthread 定时事件）

**组装要点**（已用 gone/api/src/aio_socket_link.cpp + link_timer_op.cpp 交叉验证）：
1. 定时器线程周期：`check_reconnect`(仅 is_free) + `check_heart_timeout`(仅 is_work) + `check_heart_send`(仅 is_work)
2. 心跳超时：`check_timeout` 返回 true → 投 LINK_CLOSE → 接收线程 `close_ch` → `deal_ch_closed` → `set_disconnected`
3. 物理断线：`check_reconnect` 返回 true → 投 LINK_CONNECT → 接收线程 `connect_ch` → 成功 `set_connected` + `start_ch` + 重新登录
4. 心跳维持：接收线程 `deal_msg` 解析心跳应答 → `on_heart_msg`；业务消息 → `on_com_msg`（**手动调，aio_tcp 不自动**）

**关键衔接约束**：
- ⚠️ aio_tcp 的 `on_msg` 被注释（网络范式 §6），靠业务消息维持活性须手动调 `on_com_msg`
- reconnect_ctl 首次连接门：`m_happen_connected==0` 时不重连，首次 connect 失败需业务处理（网络范式 §7）
- `set_disconnected` 必须在 `deal_ch_closed`（非 `deal_ch_closing`）调（网络范式 §7）
- `check_reconnect` 在定时器线程判定后投递事件，实际 `connect_ch` 在接收线程执行（线程范式 + 网络范式衔接）——**业务层不要在定时器线程直接调 connect_ch**，会与接收线程的 `deal_msg` 竞争 ch 状态

## 关于"多线程流水线"（不是架构范式，是使用范式的组合应用）

队列 + 线程 + 内存池 的组合（生产者-消费者）是**使用范式的组合应用**，不是系统级架构范式。三者独立，按需组合：

- 队列使用范式 → 队列.md
- 线程使用范式 → 线程.md
- 内存池使用范式 → 内存池.md

组合示例：线程从内存池 `take` 对象 → 填数据 → 队列 `write_mth` 投递 → 消费线程 `read_get` → 处理 → `release`。各步用法见各自使用范式，本文件不展开。

> 之前版本把"多线程流水线"当作架构范式并与使用模式混写，已修正：使用模式归各使用范式文档，本文件只做系统级组装。
