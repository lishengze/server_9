## 1. 项目背景与目标

### 1.1 业务背景

券商在为投资者提供 A 股交易通道时，需要对接多家厂商的柜台系统。这些柜台系统按性能等级大致分为：

| 等级 | 厂商 | 特点 |
|---|---|---|
| **极速柜台** | 个微软件、FPGA 硬件 | 软硬件协同，毫秒级延迟，适合程序化交易、量化、做市 |
| **综合柜台** | 第三方综合柜台（项目内称"98 柜台"） | 功能齐全，支持所有交易类型和查询，延迟一般 |

同一券商在不同场景下需要按策略路由：
- 优先使用极速柜台（延迟敏感）
- 极速柜台离线 / 不支持时，自动降级到综合柜台
- 查询（持仓、资金、成交、委托）只能走综合柜台
- BSE（北京证券交易所）必须走综合柜台

业务方还关心：
- **多租户**：一家券商服多个投资者，需要共享单条柜台链路
- **多接入方式**：普通内核套接字 / Solarflare TCPDirect 内核旁路（低延迟）
- **链接冗余**：主备地址，断线自动切换
- **异步回报**：委托 / 成交 / 撤单 / 链接状态等通过回调实时通知，不轮询
- **高可用**：单一柜台故障不影响整体服务

### 1.2 系统目标

提供统一的 C++ 交易 API 库，封装上述多柜台、多接入方式的复杂性，向业务方提供一致、可靠、低延迟的编程接口：
- **统一接口**：业务方写一份委托代码，跨柜台类型通用
- **自动降级**：单柜台故障不导致业务中断
- **链接可靠**：自动重连 + 主备切换
- **事件驱动**：异步回报回调，业务方无需轮询
- **可配置**：柜台类型、接入方式、性能参数全部可配

### 1.3 系统边界

**包含**：
- 多柜台协议适配（极速柜台 + 综合柜台）
- 多种 IO 模型（普通 socket、TCPDirect）
- 登录流程编排（AGW 登录 + 投资者登录）
- 链接管理（重连、心跳、主备切换）
- 异步回报分发
- 日志与诊断

**不包含**：
- 业务策略（风控、撤单算法等）
- 上层应用（UI、订单管理、撮合逻辑等）
- 柜台协议本身的定义（由厂商提供）
- 行情数据接入
- 结算、对账等

### 1.4 术语定义

| 术语 | 含义 |
|---|---|
| 投资者 / 客户 | 在券商开户的个人或机构，使用本系统进行股票交易 |
| 柜台 | 券商侧的订单处理系统，负责与交易所通信 |
| 综合柜台 | 提供完整交易功能（含查询）的传统柜台（项目内"98 柜台"） |
| 极速柜台 | 软硬件协同的极速柜台（个微 / FPGA） |
| AGW 用户 | 综合柜台的"网关用户"身份，代理投资者身份 |
| AGW 登录 | 用 AGW 用户身份在综合柜台登录 |
| 投资者登录 | 用投资者身份在对应柜台登录 |
| 委托 | 投资者发起的买入 / 卖出 / ETF / BSE 等订单请求 |
| 撤单 | 撤销已报出的未成交委托 |
| 成交 | 交易所撮合成功后返回的成交记录 |
| 委托回报 | 委托从报出到成交 / 废单的中间状态变化 |
| 主备地址 | 同一柜台可配置主备两个 IP:PORT，主失败时切备 |
| 降级 | 极速柜台不可用时，自动转综合柜台 |
| TCPDirect | Solarflare 网卡的内核旁路协议，绕过内核协议栈降低延迟 |
| 多租户 | 单一 API 实例服务多个投资者（FPGA 网关模式） |
| 共享接入 | FPGA 网关模式下，多投资者共用一条柜台链路 |

## 2. 业务场景

### 2.1 角色

| 角色 | 关注点 |
|---|---|
| **程序化交易者** | 低延迟、稳定、自动故障处理 |
| **量化机构** | 高吞吐、批量下单、多策略并发 |
| **券商运营方** | 多客户接入、统一接入成本、审计追溯 |
| **系统集成方** | 易用的 C++ 接口、稳定的服务质量 |

### 2.2 主要业务场景

#### 场景 A：个人高频交易者（FPGA 直连）
- 单账户单柜台
- 极致低延迟（FPGA + TCPDirect）
- 单一链接，不需要多租户

#### 场景 B：多客户券商（FPGA 网关）
- 多个投资者共用一台 FPGA 设备
- 共享接入（一条链路服务多客户）
- 高吞吐需求

#### 场景 C：使用软件柜台（个微直连）
- 中小型量化机构
- 不需要 FPGA 硬件投入
- 接受普通 socket 延迟

#### 场景 D：仅使用综合柜台（98 直连）
- 中长线交易、查询为主
- 业务以查询和撤单为主，委托走综合柜台
- 不需要极速柜台

### 2.3 关键业务场景选择矩阵

| 业务类型 | 柜台选型 | 接入方式 | 多租户 |
|---|---|---|---|
| 高频 / 量化 | FPGA | TCPDirect / socket | 否（直连） |
| 多客户券商 | FPGA | socket（共享） | 是（网关） |
| 软件柜台 | 个微 | socket | 否（直连） |
| 通用业务 | 98 | socket | 否（直连） |

> **业务约束**：极速柜台不提供的业务类型（ETF、BSE 业务、查询等）必须自动降级到综合柜台；用户无需手动判断。

## 3. 功能性需求

### 3.1 多柜台接入

#### 3.1.1 极速柜台类型
业务方需在初始化时选择极速柜台类型：
- **FPGA 直连**（单客户、低延迟）
- **FPGA 网关**（多客户、共享接入）
- **个微直连**（软件、单客户）

#### 3.1.2 接入方式
根据硬件环境选择接入方式：
- **普通 socket**：通用、兼容性好
- **TCPDirect**：需 Solarflare 网卡支持，最低延迟

#### 3.1.3 综合柜台（98 柜台）
- 恒在（每个 API 实例必须接入）
- 作为业务兜底 + 唯一查询入口
- 必有 AGW 用户身份（用于代理投资者）

#### 3.1.4 业务路由规则
| 业务类型 | 主路由 | 降级路由 |
|---|---|---|
| 买卖 | 极速柜台 | 综合柜台（极速离线/不支持时） |
| ETF 申购赎回 | 极速柜台 | 综合柜台（FPGA 不支持时） |
| BSE 北交所 | 综合柜台 | —（极速不支持） |
| 委托撤单 | 极速柜台 | 综合柜台 |
| 委托查询 | 综合柜台 | — |
| 成交查询 | 综合柜台 | — |
| 资金查询 | 综合柜台 | — |
| 持仓查询 | 综合柜台 | — |

> **业务约束**：降级对业务方透明，调用同一 API 即可。

### 3.2 登录管理

> **核心原则**：登录状态模型与链接生命周期解耦——**链接是传输层，登录状态是会话层；传输层事件（断开/重连/建立）一律不改变客户登录成功状态**（agwuser 会话与 98 链路绑定为唯一例外，见 §3.2.1）。

#### 3.2.0 登录状态模型（核心不变量）

系统维护三类登录状态与一个独立故障维度：

| 状态 | 范围 | 写入 | 清除条件 |
|---|---|---|---|
| agwuser 登录状态 | 实例级（98 柜台网关用户） | agwuser 登录/重登成功 | 用户登出不触及；**98 断链时复位**（会话与链路绑定，"曾成功登录过"标志 have_agw_ok_ 保持、驱动重连重发）；agwuser 重登被柜台明确拒绝时复位+关链（后台契约下正常不发生，§3.2.5） |
| 客户 98 登录状态 | 每客户（资金账号+分支机构） | 98 客户登录成功 | **仅**用户主动登出。载体：cust_login_map_ **成员不移除**，val 即登录状态（**0=未登录，1=已登出，2=登录成功**） |
| 客户柜台登录状态 | 每客户 × 极速柜台（fpga/个微） | 极速客户登录成功 | **仅**用户主动登出（→已登出）；**内部重登被拒 → 清除成功状态(→NONE)+回调失败+不再自动重登**；内部重登在途不降级状态、断线保持成功态。载体：`log_state_ctl` 单原子字（状态位+在途位），行为判定一律 `is_logined()` |
| fpga 柜台状态 | 每客户 × 板卡（独立故障维度） | FPGA 状态推送（1-正常 / 2-故障 / 3-故障切换柜台；推送用户字段空 = 板卡级，遍历该板卡客户更新，2/3 均为不可用态） | FPGA 状态推送维护，**不触碰登录状态**；每次更新经柜台状态回调通知用户（§3.6） |

**状态字典与判定约定**：
- `login_state` 与 98 map val 字典：`0=未登录（从未），1=已登出（曾成功后登出），2=登录成功`——pending 与 login_state 为**正交字段**（在途来源 vs 结果状态），各自独立取值
- **实现约定**：login_state 的行为判定一律写 `==2` / `!=2`，不对 0/1 写行为分支（登出设置点与日志/诊断除外）——1=已登出 为纯审计信息，无行为差异

**不变量**：
- 客户一旦登录成功，**保持登录成功状态**，直至用户主动登出（或柜台明确拒绝重登的终局处理）。
- 链接断开 / 重连 / 链接建立，一律**不清除任何客户登录成功状态**（agwuser 会话与 98 链路绑定为唯一例外）。
- 登录状态 ≠ 链路可用性：业务请求需同时校验登录状态与对应链接状态（§3.2.6），任一不满足即拒绝。
- 用户登出**不删除客户信息**（仅修改登录状态；gateway 客户表对象保留）。

#### 3.2.1 agwuser 登录（98 柜台网关用户）
- **目的**：用综合柜台的"网关用户"身份登录，拿到投资者代登录凭证（session）
- **时机**：随首次用户 login() 同步发起（等待结果）；此后 login() 对该步骤幂等跳过
- **超时**：可配置（默认 10 秒，最小 5 秒）
- **状态保持**：agwuser 登录会话与 98 链接绑定——断链时 `agw_login_state` 复位（会话失效；在途则带断链错误码解锁同步等待方），"曾成功登录过"标志（have_agw_ok_）保持；98 链接重连时若曾成功登录过 → 重新发起 agwuser 登录（CAS 占位与用户线程互斥，先占者投递；刷新会话，成功前 98 业务按未登录 agw 拒绝）
- **回报同步与分区去重（2026-10-12 接入机制对齐 api-dy；2026-10-13 RUL-30 并入去重）**：agwuser 登录成功后按配置发送 AgwMsgSync（`counter98_report_sync`：分区号→回报记录号起点，{0:-1} 表示同步全部分区）；**每投递一条下行回报记录**（委托确认 290001 / 撤单应答 190001 / 成交回报 210115，均携带 AgwMsgOrderReport 基类分区/记录号；查询应答无该字段不参与）经 `consume_report_pos` 按分区推进已消费位置——该位置**一图两用：去重状态 + 同步断点**（记录号 ≤ 该分区已存值 → 判定重复回报丢弃；≤0 视为未填直通不判重；分区无记录登记投递；> 已存值推进并投递），98 断链重连重登后 AgwMsgSync 按断点续传（重放记录号 > 断点，不误杀）；`counter98_mode=1`（快速登录）跳过回报同步，`counter98_mode=0` 且无分区配置同样跳过（"不需要同步"不算失败，此时 map 仍随回报推进、去重照常生效）。**需要同步而发送失败 = agw 登录失败**：置真实错误码 + 复位在途状态(1→0) + 关 98 链——**agw 成功标志(state=2/have_agw_ok_)在 sync 成功后才置位**，故失败路径不置位，重连后不自动重登 agw，由用户重新 login() 发起（与真实 agw 登录失败同语义，RUL-28）；同步等待方经 login 返回码读到真实失败原因（先复位后关链，断链路径不覆盖错误码）。SyncFinish 到达经 `on_event(report_sync_finish)` 回调用户（到达驱动通知，断点推进不依赖该应答）。断点仅内存态——进程重启后从配置起点重新同步
- **重登窗口期**（新会话应答到达前）的 98 业务请求处理见 §3.2.6

#### 3.2.2 投资者登录（分级流程 + 步骤跳过）
- **时机**：业务方主动调用（可多次，每次支持不同投资者）
- **流程**（每步先检查该步骤对应登录状态，**已成功则跳过进入下一步**）：
  1. agwuser 登录（98）：已成功 → 跳过
  2. 98 客户登录：该客户已成功 → 跳过
  3. 极速柜台客户登录（fpga/个微）：该客户已成功 → 跳过；FPGA 柜台状态非正常（fpga_state=2-故障 / 3-故障切换柜台）→ 不登录 FPGA，98 登录成功即成功（98 降级模式；登录状态位不变，恢复后由用户重新 login 走正常 FPGA 登录）
  4. 全部已成功（重复登录）→ 幂等回调成功，不发包
- **回调保证**：每个用户发起的登录请求（含重复登录）必有最终回调（成功或失败）；接口同步返回失败的场景除外
- **重复登录控制**：用户 login() 命中**登录成功状态**即幂等回调成功、不发包（**不看链路状态**——断线/重连窗口内同样幂等）
- **在途互斥与登录来源**——在途标记为**账户级位标志**（用户在途 USER=0x10 / 重连在途 RELOGIN=0x20），与登录状态位（低 2 位）**组合编码在单原子字 `log_state_ctl`** 中（**仅维护在柜台客户对象上**，direct/个微单客户一份；**98 步骤不设在途缓存**——账户一旦成功登录（val==OK）永不再次登录，98 步骤不存在需互斥的在途状态；每个 98 成功应答均投递柜台登录事件，重复事件由柜台状态机 S1 合并 / S2 幂等消化）。三场景：
  - **S1 未成功 + 用户并发登录（同账户）**：首个请求 CAS 置用户在途并发包；后续并发请求**互斥不发**（合并），**共享首个应答回调**（按资金账号+分支机构归因，不承诺逐请求回调）。互斥载体为柜台客户对象——direct/个微单客户对象恒在；gateway 客户对象在**首个成功应答**时入库，入库前的并发首登缺少互斥载体（重复事件各自发送，重复成功应答命中 S2 幂等可能再次回调成功——已知实现偏差，见 [LOGIN_COMPLIANCE.md](LOGIN_COMPLIANCE.md)）
  - **S2 已成功 + 用户再登录**：直接幂等回调成功，不发包（不看链路状态，含断线/重连窗口、FPGA 下线降级场景）
  - **S3 已成功 + 断线重连 + 内部自动重登**：在途无 → 置重连在途并发包（登录状态保持成功态不降级）；在途为用户在途 → 合并不发包；非成功状态 → 静默终止
  - **断链清除（配套必要规则）**：链接断开时**清除该链接上的全部登录在途标记**（用户在途/重连在途 → 无在途）；被清除的用户在途请求作废、无登录回调（经 on_link_status 感知）
- **更换账户**：fpga 直连与个微（单客户模式）**绑定过账户**（曾成功登录/在途，含已登出）后，异账户登录一律**拒绝**（柜台步骤同步判定：NOT_LOG_CUST + on_login 失败回调，**不向极速柜台发包**）；同账户流程不受影响，从未登录过则首登不受限；换号 = 销毁 API 实例重建。98 步骤先于柜台判定执行，被拒的异账户其 98 登录已经发出并可能成功（98 map 留下该账户 OK 成员——无行为影响，显式登出可清理）。gateway 模式天然多客户共存

#### 3.2.3 登录回调语义（按发起方界定）
| 发起方 | 成功 | 失败 |
|---|---|---|
| 用户 login() | 必回调 on_login 成功 | 必回调 on_login 失败（接口同步返回失败的除外） |
| 内部重登（断线重连自动发起） | **不回调**（用户经链接状态事件感知） | 必回调 on_login 失败 |

- 是否回调仅取决于发起方与结果；用户在途位（USER）承担在途互斥与来源判定（§3.2.2 三场景）
- **回调归因**：在途位解决"是否回调"；回调归因按应答中的（资金账号+分支机构）定位客户、不新增来源字段——用户收到"未预期发起"的登录失败回调即内部重登失败（约定写入用户文档）
- **回调例外**：①同账户并发登录合并，仅回调一次（S1，按账户归因，不承诺逐请求回调；gateway 新客户入库前并发与 98 重复成功应答场景下可能重复回调成功，见 LOGIN_COMPLIANCE）；②断链作废的在途用户登录无登录回调（经链接状态事件感知）

#### 3.2.4 用户主动登出
- **接口**：`logout(const LogoutReq&)` → `on_logout(const LogoutAns&)`
- **语义**：
  1. 清除该客户的 **98 登录成功状态**
  2. 清除该客户的**极速柜台（fpga/个微）登录成功状态**
  3. **不影响** agwuser 登录状态
  4. fpga 直连模式：**关闭与 FPGA 的核心链接（core）**，不影响 fpga 网关链接（GW）
  5. 不删除客户信息，仅修改登录状态
- **登出规则**：
  - **不向柜台发送协议登出消息**（纯 API 本地状态操作，on_logout 失败仅源于门控拒绝）
  - fpga 侧**不退出"曾成功登录过"集合**（客户信息/对象保留，仅置登录状态；重登资格由登录状态门控，重登基数 = 登录成功状态）
  - 98 侧 cust_login_map_ **成员不移除**，val 为登录状态载体（**登出置 LOGOUT，登录成功置 OK**；与 fpga 侧"对象保留+状态字段"模型统一）
  - 个微模式：**关闭个微链接**（与 fpga direct 关 core 对称）
  - **门控（两层编排，柜台层先行）**：①柜台层 `log_state_ctl.to_logout`——**用户在途登录** → 登出失败（STATE_LIMITED，无回调）；direct 已绑定账户不匹配 → 登出失败（NO_CUST，无回调）；**重连在途** → 允许登出（置 LOGOUT 并清在途位，迟到的重登应答按 LOGOUT 忽略）；未登录/已登出/offline 降级账户/未绑定 → 幂等成功；②98 层 `deal_logout_req`——cust_login_map 无该客户成员（**从未成功登录过**）→ 登出失败（同步返回 NOT_LOG_CUST，无回调）；有成员（含已登出）→ val→LOGOUT；③**98 agwuser 不支持登出**（登出不影响 agwuser 登录状态）。编排顺序：**柜台层 → 98 层 → on_logout 成功回调**（同步本地操作；柜台层先行保证拒绝路径零状态变更）

#### 3.2.5 断线重连与重新登录矩阵
| 链接 | 重连后动作 | 状态处理 |
|---|---|---|
| 98 网关链接 | 曾成功登录过（have_agw_ok_）→ 重新发起 agwuser 登录 | agwuser 登录状态断链已复位（会话与链路绑定，§3.2.1）；已成功登录的 98 客户保持状态、**不需要重新登录** |
| fpga 网关链接（direct/gateway） | 无条件重取证券信息；客户为登录成功状态**且柜台状态正常**（fpga_state=1，2/3 不可用） → 重新发起客户登录 | 不清除客户登录状态；gateway 模式若有客户曾成功登录 fpga，**至少保证一个客户**在该链接重新登录（**投递成功即算**；全部曾成功客户当前均柜台不可用(2/3)/已登出时豁免；应登>0 且全投递失败才关链重来；**地址切换（have_switch=1）时任一投递失败即关链重来**） |
| fpga 核心链接（direct） | 客户为登录成功状态**且柜台状态正常**（fpga_state=1，2/3 不可用） → 方可重连 | 不清除客户登录状态（GW 断链不影响 core 会话与交易） |
| 个微链接 | 客户为登录成功状态 → 重新发起客户登录 | 不清除客户登录状态 |

- **内部重登被柜拒绝（终局语义）**：清除登录成功状态(→NONE) + 回调失败 + **不再自动重登**（重连的内部登录对非成功态静默终止），由客户处理或重新登录。后台契约下正常不发生（曾成功客户重连重登不拒，§6.1）；一旦发生视为异常，交由用户决策。**登录失败一律不关链**。内部重登在途期间登录状态不降级（恒成功态；经 `log_state_ctl` 单原子字位编码保证）
- **窗口期原则**：链接建立成功至重登成功之间，API 不做窗口期拦截——业务请求放行、由后台明确拒绝（适用于所有柜台；需后台保证拒绝为明确应答，不静默丢弃）

#### 3.2.6 业务门控（登录状态 × 链接状态）
- 委托/撤单等用户请求必须校验：对应柜台**客户登录成功状态** + 对应**链接状态**，任一不满足按对应错误码拒绝
- **降级矩阵**：仅 fpga 柜台状态**非正常**（fpga_state=2-故障 / 3-故障切换柜台 → COUNTER_OFFLINE）与**柜台不支持**（UNSUPPORTED_OP）降级 98；fpga **链接断开为硬失败**（LINK_DISCONNECTED，不降级）
- 98 侧业务（查询/降级）登录前置：98 链接已建立 + agw 用户登录成功（NOT_LOG_AGW）；"账户登录成功过"检查（have_cust_login）暂未启用（待正式 98 协议确认后统一，见 LOGIN_COMPLIANCE）

#### 3.2.7 状态字典汇总
- **两套正交字典**：
  - 在途位（登录发起方，`log_state_ctl` 高位标志）：无在途（0）/ 用户在途（USER=0x10）/ 重连在途（RELOGIN=0x20）
  - 登录结果状态（`log_state_ctl` 低 2 位 / 98 map val）：`0=未登录（从未），1=已登出（曾成功后登出），2=登录成功`
- **实现约定**：login_state 的**行为判定一律写 `==2` / `!=2`**，不对 0/1 写行为分支（登出置 1 的设置点、日志/诊断除外）——由此 1=已登出 为纯审计信息（"从未登录"与"已登出"在全部行为中无差异），语义无歧义
- **fpga 柜台状态字典**（`fpga_state`，独立故障维度，g1dictdefine.h `G1_FPGA_USER_STATE_*`）：`1=正常，2=故障，3=故障切换柜台`——行为判定一律写 `==正常` / `!=正常`（2/3 同为不可用态：拒单/降级 98/禁重登/禁重拨；fpga 直连收到 2/3 关闭 fpga 核心链接）

### 3.3 委托管理

#### 3.3.1 买卖委托
- **业务输入**：买卖方向、证券代码、价格、数量、资金账号、股东账号等
- **业务规则**：
  - 必须先 AGW 登录 + 投资者登录
  - 极速柜台支持时优先发送；不支持（FPGA 不支持 ETF / BSE）或极速离线时自动改投综合柜台
- **业务方感知**：调用 API，传入委托参数，立即返回成功/失败；最终结果（已成 / 废单）通过回调通知

#### 3.3.2 ETF 申购赎回
- 业务输入同买卖委托
- 业务规则：FPGA 不支持 ETF，FPGA 网关模式下自动降级到综合柜台

#### 3.3.3 BSE 北交所委托
- 业务输入同买卖委托
- 业务规则：极速柜台均不支持 BSE，必须走综合柜台

#### 3.3.4 委托回报
- **触发**：委托从报出到成 / 废的中间状态变化
- **推送方**：极速柜台（极速优先）+ 综合柜台（兜底时）
- **业务内容**：委托状态、错误码、成交部分信息
- **业务方接收**：通过回调（异步事件）

### 3.4 撤单管理

- **业务输入**：原委托号（柜台流水号）、资金账号、股东账号
- **业务规则**：与买卖委托相同的降级逻辑
- **柜台支持域**：**FPGA 与个微柜台仅支持系统委托号撤单**（`order_sys_no`），不支持客户私有号撤单——`order_sys_no≤0` 的撤单请求 FPGA/个微本地拒绝参数错误（不发单、INVALID_PARAM 非降级码不降 98，RUL-36/37）；**98 支持双键定位**（`order_sys_no`/`client_seq_id`，单键场景交柜台裁决）
- **业务方感知**：同买卖委托

### 3.6 推送与回调

业务方在初始化时注册回调函数，API 实例通过以下回调事件异步通知：

| 事件 | 含义 | 触发时机 |
|---|---|---|
| 登录结果 | 投资者登录的最终结果 | 用户发起的登录流程结束（成功 / 任一步失败）；内部重登失败（内部重登成功不回调，§3.2.3） |
| 登出结果 | 用户主动登出的结果 | 登出流程结束（成功 / 失败） |
| 委托回报 | 委托状态变化 | 极速 / 综合柜台推送 |
| 成交回报 | 成交产生 | 极速 / 综合柜台推送 |
| 撤单响应 | 撤单成功 / 废单 | 极速 / 综合柜台推送 |
| 委托查询应答 | 委托查询结果分批返回 | 综合柜台推送 |
| 成交查询应答 | 成交查询结果分批返回 | 综合柜台推送 |
| 资金查询应答 | 资金查询结果 | 综合柜台推送（单条返回） |
| 持仓查询应答 | 持仓查询结果分批返回 | 综合柜台推送 |
| 扩展查询应答（6 类） | 最大可委托数/总资产/可取资金/两融保证金/资产负债/两融最大可委托数查询结果 | 综合柜台推送（98 扩展查询，2026-10-12；单条或按币种多条一次返回，无分页） |
| 链接状态 | 链接建立 / 断开 | 链接事件发生 |
| 回报同步完成 | 98 回报同步流程完成（`on_event(report_sync_finish)`，err_code=0；同步发送失败不回调，该失败按 agw 登录失败处理） | 98 agw 登录后 SyncFinish 应答到达 |
| 柜台状态 | fpga 柜台客户状态变化（`on_trade_counter`：柜台类型 + 分支机构 + 资金账号 + 状态 1-正常/2-故障/3-故障切换柜台） | FPGA 状态推送到达（含恢复推送；板卡级推送对已登录客户逐个回调） |
| 通用错误 | 业务异常 / 证券信息异常 | 异常发生 |

#### 推送模式选择
- **直接模式**：业务线程同步调用回调（多线程并发）
- **队列模式**：回调入队，独立线程消费（保证业务线程不阻塞）

### 3.7 链接管理

#### 3.7.1 链接冗余
- 每个柜台支持**主备两个地址**（IP + 端口）
- 主地址不可达时自动切换备地址
- 备地址失败后回到主地址

#### 3.7.2 链接保活
- **心跳**：定时发送心跳消息（默认 5 秒间隔）
- **心跳超时**：超时次数记入重连计数

#### 3.7.3 链接重连
- 链接断开后自动发起重连
- 同地址连续失败达到阈值（可配置）→ 切备地址
- 备地址失败后回到主地址继续重连
- 重连过程中业务持续可提交（内部排队），链接恢复后批量发送

#### 3.7.4 链接状态回调
业务方通过链接状态回调感知：
- 链接建立成功 / 断开
- 业务方可在断开时停止业务、恢复后重启

### 3.8 容错与降级

| 故障场景 | 自动处理 |
|---|---|
| 极速柜台离线 | 买卖 / 撤单自动改投综合柜台 |
| 极速柜台返回"柜台离线 / 不支持" | 自动改投综合柜台 |
| 极速柜台主地址不可达 | 切备地址重连 |
| 综合柜台断开 | 重连；agwuser/客户登录状态保持；重连后按 §3.2.5 重发 agwuser 登录 |
| 极速柜台链接断开 | 重连；客户登录状态保持；重连后按 §3.2.5 矩阵重登 |
| AGW 登录失败 | 同步接口返回失败并关闭 98 链接（会话与链路绑定）；重连后曾成功过则自动重发 agw 登录，从未成功则等用户重新 login() |
| 投资者登录失败 | 通过登录回调通知业务方（不静默） |
| 内部重登失败 | 通过登录回调通知业务方（内部重登成功不回调，§3.2.3） |
| 用户登出失败 | 通过登出回调通知业务方（不静默） |
| 队列满 | 业务方调用立即返回"队列满"错误，不阻塞 |

### 3.9 日志与诊断

- **API 实例级日志**：每个实例有独立日志目录，命名 = 实例名
- **日志级别**：可配置（DEBUG / INFO / WARN / ERROR）
- **异步写日志**：默认队列异步写（不阻塞业务线程）
- **错误诊断**：每个错误码对应明确的错误描述，业务方可查文档

### 3.10 配置管理

业务方通过配置接口设置：
- **柜台选型**：极速柜台类型 + 接入方式
- **市场**：上海 / 深交所
- **网络地址**：综合柜台 + 极速柜台 + 备地址
- **AGW 用户**：用户名 + 密码
- **登录超时**：AGW 登录等待时间
- **回调模式**：直接 / 队列 + 队列大小
- **CPU 亲和**：业务线程 / 回调线程绑核
- **队列大小**：发送 / 回调队列（MB）
- **心跳 / 重连**：间隔、超时阈值
- **日志**：目录、级别、队列大小

### 3.11 关闭流程

业务方主动停止服务时：
- 停止业务回调线程
- 关闭所有链接
- 停止所有业务线程
- 关闭日志
- 释放所有资源

## 4. 非功能性需求

### 4.1 性能

| 指标 | 目标 | 备注 |
|---|---|---|
| 买卖委托延迟 | < 5ms（FPGA） / < 50ms（98） | 单次 API 调用 → 队列 |
| 业务吞吐 | 单实例 ≥ 1000 笔/秒 | 队列模式无阻塞 |
| 内存占用 | < 200MB / 实例 | 典型配置 |
| 启动时间 | < 3 秒 | 实例启动 → AGW 登录完成 |
| 关闭时间 | < 2 秒 | 业务方主动停止服务完整流程 |

### 4.2 可靠性

| 指标 | 目标 |
|---|---|
| 链接可用性 | 单链接 ≥ 99.9%（自动重连 + 主备） |
| 综合柜台故障恢复 | 极速柜台 + 综合柜台双故障不可恢复时由业务方处理 |
| 进程异常退出 | 资源全释放（无链接泄漏） |
| 队列满处理 | 立即返回错误码，不阻塞业务线程 |

### 4.3 可维护性

- **统一接口**：业务方使用同一套 API 跨柜台工作
- **配置驱动**：柜台选型由配置决定，无需修改代码
- **日志可定位**：每条日志带实例名、级别、时间
- **错误码可解释**：每个错误码对应明确的错误描述

### 4.4 可移植性

- **操作系统**：Linux（依赖 Linux 套接字、epoll、timerfd）
- **CPU 架构**：x86_64（支持 TCPDirect 时需 Solarflare NIC）
- **编译器**：GCC / Clang，C++17

### 4.5 安全性

- **AGW 密码**：API 配置中存储（业务方负责保护配置安全）
- **链接传输**：依赖底层 TCP（不支持 TLS 由本系统加密；如需加密由业务方叠加）
- **会话管理**：AGW session 仅内存持有，不持久化
- **多租户隔离**：FPGA 网关模式不同客户通过 user_id 隔离

## 5. 业务约束与限制

### 5.1 协议约束
- 极速柜台协议（个微 / FPGA）由厂商定义，外部未提供前系统留空
- 综合柜台 98 协议由第三方提供，外部未提供前系统留空
- 协议变更时需修改对应柜台适配层，业务接口不变

### 5.2 业务时间约束
- 交易日：周一至周五（节假日休市）
- 交易时段：9:30-11:30, 13:00-15:00（A 股）
- 非交易时段：业务方可调用查询，调用委托会失败（柜台拒绝）

### 5.3 业务规模约束
- 单实例支持的投资者数：FPGA 网关模式 ≥ 1000
- 单实例支持的并发委托：≥ 5000 笔 / 秒
- 单实例持有的链接数：≤ 5（98 + 极速 + 极速GW + 主备）

### 5.4 不变量
- 登录成功状态**仅能被用户主动登出清除**（→已登出）或柜台明确拒绝重登的终局处理（§3.2.5）；链接断开/重连/建立不清除任何**客户**登录状态（§3.2.0；agwuser 会话与 98 链接绑定为例外，断链复位，§3.2.1）
- FPGA 柜台状态为独立故障维度（1-正常/2-故障/3-故障切换柜台，2/3 同为不可用态），不改变登录成功状态
- 用户登出不影响 agwuser 登录状态；不删除客户信息
- AGW 登录状态在实例内单次有效
- 投资者登录在 AGW 登录后才可能成功
- BSE 业务只能走综合柜台
- 查询只能走综合柜台
- 链接断开时业务方可继续调用，但请求会失败（登录状态保持，业务被链接状态门控拒绝）

### 5.5 不在范围内
- 投资者管理（开户、销户）
- 资金管理（银证转账、保证金）
- 风控（持仓限额、撤单限制）
- 行情数据
- 结算、对账
- 监管报送

## 6. 假设与依赖

### 6.1 外部依赖
- 极速柜台厂商（个微 / FPGA）提供协议 + 驱动
- 综合柜台厂商提供协议
- Solarflare NIC（如果用 TCPDirect 模式）
- Linux 2.6+ 内核（epoll / timerfd）
- 必须基于 common 基础库代码 和 solarflare 基础库代码 开发

### 6.2 后台契约（fgw 侧）
- 曾成功客户在重连后的重登不拒绝（拒绝仅源于同链接两次登录）——API 内部重登被拒按终局处理（清状态+回调+不再重登），视为异常
- fgw 重启后同一账户的 board_no / user_id 当日不变（变化时 API 按异常处理：回调失败 + 不更新映射）
- "同连接不可换号"不变式由 API 侧单客户模式拒绝换号保证（§3.2.2）
- 重登窗口期内放行的业务请求，后台以明确应答拒绝（不静默丢弃）

### 6.3 业务假设
- 业务方知道 A 股交易规则
- 业务方理解 98 / 极速 / TCPDirect 等技术选型
- 业务方负责部署、配置和运维
- 业务方账户已在券商开户

### 6.4 风险
- 协议变更风险：柜台协议升级时需同步更新
- 性能风险：TCPDirect 部署复杂，需专业运维
- 监管风险：交易异常时需追溯（依赖日志完整性）

## 8. 业务流程图

### 8.1 API 实例启动流程
```
业务方创建 API 实例
  ↓
设置配置（柜台类型 / 地址 / AGW 用户 / 回调）
  ↓
启动 API 实例
  ↓
  ├─ 启动回调线程
  ├─ 注册业务 timerfd
  ├─ 同步连接综合柜台（仅建链）
  ├─ 启动综合柜台引擎线程
  ├─ 启动极速柜台引擎线程
  └─ 实例就绪（agw 登录随首次用户 login() 同步发起, §3.2.1）
       └─ 任一步启动失败 → 逆序回退已启动模块, 允许原地重试
```

### 8.2 投资者登录流程（分级跳过）
```
业务方调用 投资者登录(账户信息)
  ↓
步骤1: agwuser 登录状态 == 已成功 ? ──是──→ 跳过
  │否                                       │
  ↓ 发起 agwuser 登录(同步等待)             │
  ├─ 失败 → 同步返回错误 ←──────────────────┤
  ↓ 成功                                   │
步骤2: 该客户 98 登录状态 == 已成功 ? ──是──→ 跳过
  │否                                       │
  ↓ 构造账户登录事件 → 综合柜台代登录        │
  ├─ 失败 → 回调 登录失败 ←─────────────────┤
  ↓ 成功                                   │
步骤3: 该客户柜台登录状态 == 已成功 ? ──是──→ 跳过
  │否                                       │
  ├─ FPGA 柜台状态非正常(fpga_state=2/3) → 98 成功即成功 ─→ 回调 登录成功(降级模式, 状态位不变)
  ↓ 发起极速柜台客户登录                     │
  ├─ 成功 → 回调 业务方 登录成功             │
  └─ 失败 → 回调 业务方 登录失败             │
                                          ↓
                        全部已成功(重复登录) → 幂等回调成功, 不发包
```

### 8.2a 用户主动登出流程（两层编排，柜台层先行）
```
业务方调用 登出(账户信息)
  ↓
柜台层 to_logout: 用户在途 → 同步返回 STATE_LIMITED (无回调, 流程结束)
                direct 已绑定账户不匹配 → 同步返回 NO_CUST (无回调, 流程结束)
                重连在途/未登录/已登出/未绑定 → 置 LOGOUT (清在途位) 或幂等成功
  ↓ (fpga 直连模式)
关闭 fpga 核心链接(core), 不影响 fpga 网关链接(GW)
  ↓ (个微模式)
关闭个微链接
  ↓
98 层: cust_login_map 无成员 → 同步返回 NOT_LOG_CUST (仅防御, 流程结束)
     有成员 → val→LOGOUT (成员不移除)
  ↓
agwuser 登录状态保持不变
  ↓
回调 业务方 登出结果 (on_logout)
(不向柜台发协议登出消息 / 个微关链 / 从未成功登录过 → 登出失败 NOT_LOG_CUST)
```

### 8.2b 断线重连重登流程
```
链接断开 (任何链接)
  ↓  不清除任何客户登录状态 (agwuser 会话随 98 链路失效除外), 清除该链接登录在途
timer 自动重连 (fpga core: 客户已登录且柜台状态正常方可重连, §3.2.5)
  ↓ 重连成功
  ├─ 98 链接:      agwuser 曾成功 → 重发 agwuser 登录(成功静默/失败关链)
  │                已成功 98 客户不重登
  ├─ fpga GW 链接: 重取证券信息; 已登录且柜台状态正常客户 → 重新登录(成功静默/失败按终局处理)
  │                gateway 模式: 有客户曾成功登录 fpga → 至少一个客户重登(投递成功即算)
  └─ 个微链接:     已登录客户 → 重新登录(成功静默/失败按终局处理)
```

### 8.3 买卖委托流程
```
业务方调用 买卖委托(req)
  ↓
优先发送极速柜台
  ↓
  ├─ 极速返回成功 → 业务方立即收到成功
  │  └─ 极速后续推送 委托回报
  │
  └─ 极速返回"离线 / 不支持"
     ↓
     改投综合柜台
       ├─ 综合返回成功 → 业务方立即收到成功
       │  └─ 综合后续推送 委托回报
       └─ 综合返回失败 → 业务方收到错误码
```

### 8.4 链接故障处理流程
```
极速柜台链接断开
  ↓
  ├─ 启动重连（主地址）
  │     ├─ 重连成功 → 链接状态回调（已连接）→ 业务恢复
  │     └─ 重连失败 N 次 → 切备地址
  │           ├─ 备地址重连成功 → 业务恢复
  │           └─ 备地址重连失败 → 继续切回主地址（持续重连）
  │
  └─ 业务持续收到"柜台离线"错误，可选择改投综合柜台
```

### 8.5 关闭流程
```
业务方调用 停止
  ↓
  ├─ 停止极速柜台引擎（关闭链接 + 关闭 timer）
  ├─ 停止综合柜台引擎（关闭 98 + 极速GW 链接）
  ├─ 停止业务回调线程
  └─ 关闭日志
```
