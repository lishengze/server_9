## 1. 项目背景与目标

### 1.1 业务背景

券商在为投资者提供 A 股交易通道时，需要对接多家厂商的柜台系统。这些柜台系统按性能等级大致分为：

| 等级 | 厂商 | 特点 |
|---|---|---|
| **极速柜台** | 个微软件、FPGA 硬件 | 软硬件协同，毫秒级延迟，适合程序化交易、量化、做市 |
| **综合柜台** | 第三方综合柜台（项目内称"98 柜台"） | 功能齐全，支持所有交易类型和查询，延迟一般 |

同一券商在不同场景下需要按策略路由：
- 优先使用极速柜台（延迟敏感）
- 极速柜台离线 / 不支持时，自动降级到综合柜台
- 查询（持仓、资金、成交、委托）只能走综合柜台
- BSE（北京证券交易所）必须走综合柜台

业务方还关心：
- **多租户**：一家券商服多个投资者，需要共享单条柜台链路
- **多接入方式**：普通内核套接字 / Solarflare TCPDirect 内核旁路（低延迟）
- **链接冗余**：主备地址，断线自动切换
- **异步回报**：委托 / 成交 / 撤单 / 链接状态等通过回调实时通知，不轮询
- **高可用**：单一柜台故障不影响整体服务

### 1.2 系统目标

提供统一的 C++ 交易 API 库，封装上述多柜台、多接入方式的复杂性，向业务方提供一致、可靠、低延迟的编程接口：
- **统一接口**：业务方写一份委托代码，跨柜台类型通用
- **自动降级**：单柜台故障不导致业务中断
- **链接可靠**：自动重连 + 主备切换
- **事件驱动**：异步回报回调，业务方无需轮询
- **可配置**：柜台类型、接入方式、性能参数全部可配

### 1.3 系统边界

**包含**：
- 多柜台协议适配（极速柜台 + 综合柜台）
- 多种 IO 模型（普通 socket、TCPDirect）
- 登录流程编排（AGW 登录 + 投资者登录）
- 链接管理（重连、心跳、主备切换）
- 异步回报分发
- 日志与诊断

**不包含**：
- 业务策略（风控、撤单算法等）
- 上层应用（UI、订单管理、撮合逻辑等）
- 柜台协议本身的定义（由厂商提供）
- 行情数据接入
- 结算、对账等

### 1.4 术语定义

| 术语 | 含义 |
|---|---|
| 投资者 / 客户 | 在券商开户的个人或机构，使用本系统进行股票交易 |
| 柜台 | 券商侧的订单处理系统，负责与交易所通信 |
| 综合柜台 | 提供完整交易功能（含查询）的传统柜台（项目内"98 柜台"） |
| 极速柜台 | 软硬件协同的极速柜台（个微 / FPGA） |
| AGW 用户 | 综合柜台的"网关用户"身份，代理投资者身份 |
| AGW 登录 | 用 AGW 用户身份在综合柜台登录 |
| 投资者登录 | 用投资者身份在对应柜台登录 |
| 委托 | 投资者发起的买入 / 卖出 / ETF / BSE 等订单请求 |
| 撤单 | 撤销已报出的未成交委托 |
| 成交 | 交易所撮合成功后返回的成交记录 |
| 委托回报 | 委托从报出到成交 / 废单的中间状态变化 |
| 主备地址 | 同一柜台可配置主备两个 IP:PORT，主失败时切备 |
| 降级 | 极速柜台不可用时，自动转综合柜台 |
| TCPDirect | Solarflare 网卡的内核旁路协议，绕过内核协议栈降低延迟 |
| 多租户 | 单一 API 实例服务多个投资者（FPGA 网关模式） |
| 共享接入 | FPGA 网关模式下，多投资者共用一条柜台链路 |

## 2. 业务场景

### 2.1 角色

| 角色 | 关注点 |
|---|---|
| **程序化交易者** | 低延迟、稳定、自动故障处理 |
| **量化机构** | 高吞吐、批量下单、多策略并发 |
| **券商运营方** | 多客户接入、统一接入成本、审计追溯 |
| **系统集成方** | 易用的 C++ 接口、稳定的服务质量 |

### 2.2 主要业务场景

#### 场景 A：个人高频交易者（FPGA 直连）
- 单账户单柜台
- 极致低延迟（FPGA + TCPDirect）
- 单一链接，不需要多租户

#### 场景 B：多客户券商（FPGA 网关）
- 多个投资者共用一台 FPGA 设备
- 共享接入（一条链路服务多客户）
- 高吞吐需求

#### 场景 C：使用软件柜台（个微直连）
- 中小型量化机构
- 不需要 FPGA 硬件投入
- 接受普通 socket 延迟

#### 场景 D：仅使用综合柜台（98 直连）
- 中长线交易、查询为主
- 业务以查询和撤单为主，委托走综合柜台
- 不需要极速柜台

### 2.3 关键业务场景选择矩阵

| 业务类型 | 柜台选型 | 接入方式 | 多租户 |
|---|---|---|---|
| 高频 / 量化 | FPGA | TCPDirect / socket | 否（直连） |
| 多客户券商 | FPGA | socket（共享） | 是（网关） |
| 软件柜台 | 个微 | socket | 否（直连） |
| 通用业务 | 98 | socket | 否（直连） |

> **业务约束**：极速柜台不提供的业务类型（ETF、BSE 业务、查询等）必须自动降级到综合柜台；用户无需手动判断。

## 3. 功能性需求

### 3.1 多柜台接入

#### 3.1.1 极速柜台类型
业务方需在初始化时选择极速柜台类型：
- **FPGA 直连**（单客户、低延迟）
- **FPGA 网关**（多客户、共享接入）
- **个微直连**（软件、单客户）

#### 3.1.2 接入方式
根据硬件环境选择接入方式：
- **普通 socket**：通用、兼容性好
- **TCPDirect**：需 Solarflare 网卡支持，最低延迟

#### 3.1.3 综合柜台（98 柜台）
- 恒在（每个 API 实例必须接入）
- 作为业务兜底 + 唯一查询入口
- 必有 AGW 用户身份（用于代理投资者）

#### 3.1.4 业务路由规则
| 业务类型 | 主路由 | 降级路由 |
|---|---|---|
| 买卖 | 极速柜台 | 综合柜台（极速离线/不支持时） |
| ETF 申购赎回 | 极速柜台 | 综合柜台（FPGA 不支持时） |
| BSE 北交所 | 综合柜台 | —（极速不支持） |
| 委托撤单 | 极速柜台 | 综合柜台 |
| 委托查询 | 综合柜台 | — |
| 成交查询 | 综合柜台 | — |
| 资金查询 | 综合柜台 | — |
| 持仓查询 | 综合柜台 | — |

> **业务约束**：降级对业务方透明，调用同一 API 即可。

### 3.2 登录管理

#### 3.2.1 AGW 登录
- **目的**：用综合柜台的"网关用户"身份登录，拿到投资者代登录凭证
- **时机**：API 实例启动时执行一次
- **凭证**：登录成功获得 session，所有投资者代登录都基于该 session
- **超时**：可配置（默认 10 秒，最小 5 秒）

#### 3.2.2 投资者登录
- **目的**：用具体投资者身份在对应柜台登录
- **时机**：业务方主动调用（可多次，每次支持不同投资者）
- **前置条件**：AGW 登录成功
- **流程**：
  1. 业务方传入投资者账户信息
  2. 通过综合柜台用 AGW session 代登录
  3. 综合柜台登录成功后自动触发极速柜台投资者登录
  4. 极速柜台投资者登录成功后通过回调通知业务方
- **失败处理**：任一步骤失败都通过回调告知，不静默丢弃

#### 3.2.3 登录凭证管理
- AGW session 缓存在系统内部，对业务方不可见
- 投资者账户信息业务方传入，系统内部加密传递

### 3.3 委托管理

#### 3.3.1 买卖委托
- **业务输入**：买卖方向、证券代码、价格、数量、资金账号、股东账号等
- **业务规则**：
  - 必须先 AGW 登录 + 投资者登录
  - 极速柜台支持时优先发送；不支持（FPGA 不支持 ETF / BSE）或极速离线时自动改投综合柜台
- **业务方感知**：调用 API，传入委托参数，立即返回成功/失败；最终结果（已成 / 废单）通过回调通知

#### 3.3.2 ETF 申购赎回
- 业务输入同买卖委托
- 业务规则：FPGA 不支持 ETF，FPGA 网关模式下自动降级到综合柜台

#### 3.3.3 BSE 北交所委托
- 业务输入同买卖委托
- 业务规则：极速柜台均不支持 BSE，必须走综合柜台

#### 3.3.4 委托回报
- **触发**：委托从报出到成 / 废的中间状态变化
- **推送方**：极速柜台（极速优先）+ 综合柜台（兜底时）
- **业务内容**：委托状态、错误码、成交部分信息
- **业务方接收**：通过回调（异步事件）

### 3.4 撤单管理

- **业务输入**：原委托号（柜台流水号）、资金账号、股东账号
- **业务规则**：与买卖委托相同的降级逻辑
- **业务方感知**：同买卖委托

### 3.5 查询管理

查询只能走综合柜台（极速柜台不提供查询接口）。

| 查询类型 | 输入 | 输出 | 用途 |
|---|---|---|---|
| 委托查询 | 客户请求号、委托号（可选） | 委托列表 + 批次控制 | 查当日委托状态 |
| 委托批量查询 | 客户请求号、委托号区间 | 委托列表 + 批次控制 | 查大量委托 |
| 成交查询 | 客户请求号、委托号（可选） | 成交列表 + 批次控制 | 查当日成交 |
| 成交批量查询 | 客户请求号、成交号区间 | 成交列表 + 批次控制 | 查大量成交 |
| 资金查询 | 资金账号 | 资金信息（可用、可取） | 查资金余额 |
| 持仓查询 | 资金账号、证券代码（可选） | 持仓列表 + 批次控制 | 查持仓 |

> **业务约束**：查询必须在 AGW 登录 + 投资者登录后才有意义。

### 3.6 推送与回调

业务方在初始化时注册回调函数，API 实例通过以下回调事件异步通知：

| 事件 | 含义 | 触发时机 |
|---|---|---|
| 登录结果 | 投资者登录的最终结果 | 投资者登录流程结束（成功 / 任一步失败） |
| 委托回报 | 委托状态变化 | 极速 / 综合柜台推送 |
| 成交回报 | 成交产生 | 极速 / 综合柜台推送 |
| 撤单响应 | 撤单成功 / 废单 | 极速 / 综合柜台推送 |
| 委托查询应答 | 委托查询结果分批返回 | 综合柜台推送 |
| 成交查询应答 | 成交查询结果分批返回 | 综合柜台推送 |
| 资金查询应答 | 资金查询结果 | 综合柜台推送（单条返回） |
| 持仓查询应答 | 持仓查询结果分批返回 | 综合柜台推送 |
| 链接状态 | 链接建立 / 断开 | 链接事件发生 |
| 通用错误 | 业务异常 / 证券信息异常 | 异常发生 |

#### 推送模式选择
- **直接模式**：业务线程同步调用回调（多线程并发）
- **队列模式**：回调入队，独立线程消费（保证业务线程不阻塞）

### 3.7 链接管理

#### 3.7.1 链接冗余
- 每个柜台支持**主备两个地址**（IP + 端口）
- 主地址不可达时自动切换备地址
- 备地址失败后回到主地址

#### 3.7.2 链接保活
- **心跳**：定时发送心跳消息（默认 5 秒间隔）
- **心跳超时**：超时次数记入重连计数

#### 3.7.3 链接重连
- 链接断开后自动发起重连
- 同地址连续失败达到阈值（可配置）→ 切备地址
- 备地址失败后回到主地址继续重连
- 重连过程中业务持续可提交（内部排队），链接恢复后批量发送

#### 3.7.4 链接状态回调
业务方通过链接状态回调感知：
- 链接建立成功 / 断开
- 业务方可在断开时停止业务、恢复后重启

### 3.8 容错与降级

| 故障场景 | 自动处理 |
|---|---|
| 极速柜台离线 | 买卖 / 撤单自动改投综合柜台 |
| 极速柜台返回"柜台离线 / 不支持" | 自动改投综合柜台 |
| 极速柜台主地址不可达 | 切备地址重连 |
| 综合柜台断开 | 重连，链接恢复前业务方请求失败 |
| AGW 登录失败 | 投资者登录无法进行，业务方需要重试 |
| 投资者登录失败 | 通过登录回调通知业务方（不静默） |
| 队列满 | 业务方调用立即返回"队列满"错误，不阻塞 |

### 3.9 日志与诊断

- **API 实例级日志**：每个实例有独立日志目录，命名 = 实例名
- **日志级别**：可配置（DEBUG / INFO / WARN / ERROR）
- **异步写日志**：默认队列异步写（不阻塞业务线程）
- **错误诊断**：每个错误码对应明确的错误描述，业务方可查文档

### 3.10 配置管理

业务方通过配置接口设置：
- **柜台选型**：极速柜台类型 + 接入方式
- **市场**：上海 / 深交所
- **网络地址**：综合柜台 + 极速柜台 + 备地址
- **AGW 用户**：用户名 + 密码
- **登录超时**：AGW 登录等待时间
- **回调模式**：直接 / 队列 + 队列大小
- **CPU 亲和**：业务线程 / 回调线程绑核
- **队列大小**：发送 / 回调队列（MB）
- **心跳 / 重连**：间隔、超时阈值
- **日志**：目录、级别、队列大小

### 3.11 关闭流程

业务方主动停止服务时：
- 停止业务回调线程
- 关闭所有链接
- 停止所有业务线程
- 关闭日志
- 释放所有资源

## 4. 非功能性需求

### 4.1 性能

| 指标 | 目标 | 备注 |
|---|---|---|
| 买卖委托延迟 | < 5ms（FPGA） / < 50ms（98） | 单次 API 调用 → 队列 |
| 业务吞吐 | 单实例 ≥ 1000 笔/秒 | 队列模式无阻塞 |
| 内存占用 | < 200MB / 实例 | 典型配置 |
| 启动时间 | < 3 秒 | 实例启动 → AGW 登录完成 |
| 关闭时间 | < 2 秒 | 业务方主动停止服务完整流程 |

### 4.2 可靠性

| 指标 | 目标 |
|---|---|
| 链接可用性 | 单链接 ≥ 99.9%（自动重连 + 主备） |
| 综合柜台故障恢复 | 极速柜台 + 综合柜台双故障不可恢复时由业务方处理 |
| 进程异常退出 | 资源全释放（无链接泄漏） |
| 队列满处理 | 立即返回错误码，不阻塞业务线程 |

### 4.3 可维护性

- **统一接口**：业务方使用同一套 API 跨柜台工作
- **配置驱动**：柜台选型由配置决定，无需修改代码
- **日志可定位**：每条日志带实例名、级别、时间
- **错误码可解释**：每个错误码对应明确的错误描述

### 4.4 可移植性

- **操作系统**：Linux（依赖 Linux 套接字、epoll、timerfd）
- **CPU 架构**：x86_64（支持 TCPDirect 时需 Solarflare NIC）
- **编译器**：GCC / Clang，C++17

### 4.5 安全性

- **AGW 密码**：API 配置中存储（业务方负责保护配置安全）
- **链接传输**：依赖底层 TCP（不支持 TLS 由本系统加密；如需加密由业务方叠加）
- **会话管理**：AGW session 仅内存持有，不持久化
- **多租户隔离**：FPGA 网关模式不同客户通过 user_id 隔离

## 5. 业务约束与限制

### 5.1 协议约束
- 极速柜台协议（个微 / FPGA）由厂商定义，外部未提供前系统留空
- 综合柜台 98 协议由第三方提供，外部未提供前系统留空
- 协议变更时需修改对应柜台适配层，业务接口不变

### 5.2 业务时间约束
- 交易日：周一至周五（节假日休市）
- 交易时段：9:30-11:30, 13:00-15:00（A 股）
- 非交易时段：业务方可调用查询，调用委托会失败（柜台拒绝）

### 5.3 业务规模约束
- 单实例支持的投资者数：FPGA 网关模式 ≥ 1000
- 单实例支持的并发委托：≥ 5000 笔 / 秒
- 单实例持有的链接数：≤ 5（98 + 极速 + 极速GW + 主备）

### 5.4 不变量
- AGW 登录状态在实例内单次有效
- 投资者登录在 AGW 登录后才可能成功
- BSE 业务只能走综合柜台
- 查询只能走综合柜台
- 链接断开时业务方可继续调用，但请求会失败

### 5.5 不在范围内
- 投资者管理（开户、销户）
- 资金管理（银证转账、保证金）
- 风控（持仓限额、撤单限制）
- 行情数据
- 结算、对账
- 监管报送

## 6. 假设与依赖

### 6.1 外部依赖
- 极速柜台厂商（个微 / FPGA）提供协议 + 驱动
- 综合柜台厂商提供协议
- Solarflare NIC（如果用 TCPDirect 模式）
- Linux 2.6+ 内核（epoll / timerfd）
- 必须基于 common 基础库代码 和 solarflare 基础库代码 开发

### 6.2 业务假设
- 业务方知道 A 股交易规则
- 业务方理解 98 / 极速 / TCPDirect 等技术选型
- 业务方负责部署、配置和运维
- 业务方账户已在券商开户

### 6.3 风险
- 协议变更风险：柜台协议升级时需同步更新
- 性能风险：TCPDirect 部署复杂，需专业运维
- 监管风险：交易异常时需追溯（依赖日志完整性）

## 8. 业务流程图

### 8.1 API 实例启动流程
```
业务方创建 API 实例
  ↓
设置配置（柜台类型 / 地址 / AGW 用户 / 回调）
  ↓
启动 API 实例
  ↓
  ├─ 启动回调线程
  ├─ 注册业务 timerfd
  ├─ 同步连接综合柜台（仅建链）
  ├─ 启动综合柜台引擎线程
  ├─ 启动极速柜台引擎线程
  └─ AGW 登录（同步等待应答）
       ├─ 成功 → 实例就绪
       └─ 失败 → 返回错误，引擎仍在运行，业务方可重试
```

### 8.2 投资者登录流程
```
业务方调用 投资者登录(账户信息)
  ↓
校验 AGW 已登录
  ↓
构造账户登录事件 → 投到综合柜台队列
  ↓
综合柜台收到 → 用 AGW session 代登录
  ↓
  ├─ 成功 → 构造极速柜台登录事件 → 投到极速队列
  │         极速柜台收到 → 投资者登录
  │           ├─ 成功 → 回调 业务方 登录成功
  │           └─ 失败 → 回调 业务方 登录失败
  └─ 失败 → 回调 业务方 登录失败
```

### 8.3 买卖委托流程
```
业务方调用 买卖委托(req)
  ↓
优先发送极速柜台
  ↓
  ├─ 极速返回成功 → 业务方立即收到成功
  │  └─ 极速后续推送 委托回报
  │
  └─ 极速返回"离线 / 不支持"
     ↓
     改投综合柜台
       ├─ 综合返回成功 → 业务方立即收到成功
       │  └─ 综合后续推送 委托回报
       └─ 综合返回失败 → 业务方收到错误码
```

### 8.4 链接故障处理流程
```
极速柜台链接断开
  ↓
  ├─ 启动重连（主地址）
  │     ├─ 重连成功 → 链接状态回调（已连接）→ 业务恢复
  │     └─ 重连失败 N 次 → 切备地址
  │           ├─ 备地址重连成功 → 业务恢复
  │           └─ 备地址重连失败 → 继续切回主地址（持续重连）
  │
  └─ 业务持续收到"柜台离线"错误，可选择改投综合柜台
```

### 8.5 关闭流程
```
业务方调用 停止
  ↓
  ├─ 停止业务回调线程
  ├─ 停止极速柜台引擎（关闭链接 + 关闭 timer）
  ├─ 停止综合柜台引擎（关闭 98 + 极速GW 链接）
  └─ 关闭日志
```
