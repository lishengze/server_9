## 0. 概要（TL;DR）

**一句话**：Linux 平台证券交易 API 客户端库，一个实例对接 98 柜台 + 一种极速柜台（个微软件 / FPGA 直连 / FPGA 网关 三选一），让上层策略用一套接口完成"委托、撤单、ETF、北交所、查询"全场景。

**3 个最关键约束**：
1. **1 实例 = 1 市场 = 1 会话**（决定"不能多市场实例"边界）
2. **3 种柜台 × 3 种链接类型 = 仅 5 种有效配置**（其他组合启动时拒绝）
3. **错误处理两路**：业务调用同步返回；登录/断线/异步错误走回调

---

## 1. 背景与目标 [核心]

本项目是 Linux 平台上的证券交易 API 客户端库，为上层策略系统提供统一入口，让策略能用同一套接口完成"普通买卖、ETF 申购赎回、北交所委托、查询、资金持仓管理"等所有交易动作，同时与两个后台柜台对接。[D]

**业务目标**：把策略的"我需要下个单"变成"我调用一次 X，X 会按最快路径送到正确的柜台"。[D]

**成功标准**：
- 业务方能用一份调用代码对接任一支持的柜台组合 [D]
- 极速柜台报单时延与直接连柜台相当 [D]
- 链接异常时业务方不感知，由 API 内部处理重连 [D]

## 2. 用户与场景 [推荐]

### 2.1 谁会用

- 量化策略系统 [A]
- 人工交易终端 [A]
- 行情驱动的做市系统 [A]
- 私募/资管的多账户系统（仅 FPGA 网关模式支持）[D]

> [A] 标注的 3 类用户是推断（来自常见用户分类），非用户原话。

### 2.2 典型场景

| 场景 | 关键诉求 | 适用模式 |
|---|---|---|
| 单账户量化下单 | 高吞吐低延迟 | 任意 |
| 多账户做市 | 进程内服务多客户 | 仅 FPGA 网关 |
| 异常恢复 | 链接断了不感知 | 任意 |
| ETF 跨市场套利 | 极速失败转 98 | 任意 |
| 北交所交易 | 深市市场下北交所股票 | 任意 |
| 紧急撤单 | 网络异常仍能撤 | 任意 |

[D]

### 2.3 使用流程（用户视角）

1. 准备一份配置（柜台/市场/网络参数等）[I]
2. 创建一个 API 实例 [I]
3. 启动 API（建立网络链接、登录 agw）[I]
4. 提供账户信息，发起登录 [D]
5. 等收到"登录成功"回调后，开始收发业务 [I]
6. 不用了，停止并释放实例 [I]

## 3. 外部系统与协议 [推荐]

### 3.1 98 柜台

老牌后台系统，所有券商通用。

- 一个 API 实例只连一个 98 链接 [D]
- 负责：账户登录、所有查询、资金/持仓、ETF 申购赎回（极速不支持时）、北交所委托 [I]
- 协议参考：`include/c98msg_tmp.h`

### 3.2 极速柜台（必选其一）

| 柜台类型 | 业务特点 | 链接数 | 客户支持 |
|---|---|---|---|
| 个微软件柜台 | 软件低时延 | 1 TCP | 单客户 |
| FPGA 直连柜台 | 硬件加速 | 2 个（1 GW + 1 业务）| 单客户 |
| FPGA 网关柜台 | 硬件加速 | 1 个（GW 同时承担业务）| 多客户共享 |

负责：买卖委托、撤单、委托/成交回报推送。FPGA 还负责自身客户/证券信息管理。[D]

### 3.3 两柜台关系

- 共用**一个会话 ID**（来自 98 登录）[D]
- 各自维护消息编号、连接状态 [I]
- 任一柜台断线不影响另一个 [D]
- 委托和回报优先走极速柜台 [D]

## 4. 功能需求 [核心]

### 4.1 委托类

| 业务 | 路由 | 失败处理 |
|---|---|---|
| 普通买卖委托（限价/市价/止损）[I] | 极速柜台 [D] | 极速客户状态异常 → 自动降级到 98 [D] |
| 委托撤单（用柜台原始报单号）[I] | 极速柜台 [D] | — |
| ETF 申购赎回 [D] | 先试极速，被拒自动转 98 [D] | — |
| 北交所委托 [D] | 98 柜台 [D] | — |

### 4.2 查询类（全部走 98 柜台）[D]

- 客户委托查询（按委托号）[I]
- 客户委托批量查询（按委托号区间）[I]
- 客户成交查询 [I]
- 客户成交批量查询 [I]
- 客户资金查询 [I]
- 客户持仓查询 [I]

### 4.3 推送类（异步回调）[D]

- 委托回报推送 [I]
- 成交回报推送 [I]
- 链接状态变化（断/连中/已连）[D]
- 通用错误通知（含来源 + 错误码 + 描述）[D]

### 4.4 登录

完整登录流程由 API 内部协调两个柜台自动完成，用户只需提供账户信息一次：[D]

1. 同步连接 98 柜台
2. 发起 98 agw 登录（用配置的 agw 用户名密码）
3. agw 登录成功后发起账户登录
4. 账户登录成功后发起极速柜台登录
5. 全部成功后通过回调通知用户

任一步失败通过回调通知用户，附错误码和描述。

> [A] 暂未明确：登录是否支持"重登录"语义；当前设计是一次性登录。

## 5. 非功能需求 [核心]

### 5.1 平台 [D]

- 仅支持 Linux
- 使用 epoll 等 Linux 原生异步机制 [I]

### 5.2 性能

> **本节为示例性指标**。不同程序的实际性能需求不同，**具体数字由业务方在设计阶段确定**。
> 这里列出的是**常见参考值**，用于辅助设计决策。

- 极速柜台报单时延：与直连柜台相当（局域网内可接受同步操作）[D]
- 单实例吞吐：**示例** —— 10000+ 委托/秒（实际值取决于业务场景）
- 回调路径：可配置"直调"或"队列+回调线程"两种模式 [D]

### 5.3 可靠性 [D]

- 链接断线自动重连（间隔、最大次数可配）
- 98 链接和极速链接独立重连，互不影响
- 98 链接和 FPGA GW 重连后不需要重新登录
- 个微柜台重连后需重新登录（**暂不实现**）

### 5.4 可配置性

- 所有外部地址、用户信息、超时时间、队列大小均可配置 [D]
- 配置通过类型安全的 set_attr 接口 [I]
- 启动时校验配置，配置错误立即报错 [D]

## 6. 配置与部署 [推荐]

### 6.1 部署形态 [D]

- 一个进程 = 一个 API 实例
- 一个 API 实例 = 一个 98 链接 + 一个极速柜台
- 一个市场（上海 / 深交所（含北交所））

> [A] "进程与实例 1:1" 是推断（来自当前代码结构），未与用户明确确认是否需要多实例。

### 6.2 配置项分类 [D]

- **必填**：98 地址、极速地址、市场、agw 用户名密码、API 实例名
- **fpga 必填**：fpga GW 地址
- **tcpdirect 必填**：Solarflare 网卡名
- **可调优**：心跳、重连、队列大小、CPU 亲和、回调模式

### 6.3 启动校验规则 [D]

| 规则 | 拒绝方式 |
|---|---|
| 个微柜台：极速链接类型不能是共享 | 配置校验失败 |
| FPGA 直连：极速链接类型不能是共享 | 配置校验失败 |
| FPGA 网关：极速链接类型必须是共享 | 配置校验失败 |
| AGW 登录超时必须 > 0 | 配置校验失败 |
| 市场必须是 1（上海）或 2（深市/北交所）| 配置校验失败 |
| FPGA 柜台必须配置 fpga GW 地址 | 配置校验失败 |
| 队列大小必须 > 0 | 配置校验失败 |

5 种有效配置组合参见 [apidoc/config_matrix.md](apidoc/config_matrix.md)。

## 7. 错误处理 [推荐]

> **本节按需求阶段放宽**——不规定具体错误码列表（具体分段留给设计阶段确定）。
> 这里只描述**错误如何处理**。

### 7.1 错误传递方式

- **同步返回值**：用户调用业务方法时，立即返回错误码（成功/失败）
- **异步回调**：登录完成、链接状态变化、异步错误 → 通过用户回调接口通知
- **日志**：所有错误同时写入日志（含实例名、时间戳、来源、错误码、描述）

### 7.2 错误信息最小字段

每条错误必须包含：

- **错误码**（int32，整数，0=成功，负值=失败）
- **错误描述**（人类可读字符串，长度有限）
- **错误来源**（哪个子系统：98 链接 / 极速链接 / 业务路由 / 等）

> 具体错误码分段、命名、范围 → 留给**设计阶段**确定。

### 7.3 错误处理策略 [D]

| 场景 | 策略 |
|---|---|
| 配置错误 | **fail-fast**：启动时拒绝，进程退出 |
| 链接断线 | **自动重连**：按可配间隔重试，可配最大次数 |
| 登录失败 | **回调通知**：通过 on_login 通知用户 |
| 业务路由失败 | **降级或重试**：fpga 不可用 → 降级到 98；个别委托失败 → 不影响后续 |
| 数据不一致 | **保护性失败**：宁可拒绝也不发错误请求 |

### 7.4 错误流

```
用户调用业务方法
  ↓
同步返回错误码（即时结果）

后台事件（断线/登录完成/异步错误）
  ↓
通过回调接口通知用户
```

> 同步 vs 异步——**不混淆**。

## 8. 边界与不在范围 [核心]

### 8.1 不实现 [D]

- 会话恢复（重连后 98 / FPGA 保留状态）
- 个微柜台的完整协议（暂时只预留接口，不实现）
- 98 柜台的业务消息（暂时只预留接口，不实现）
- 复杂资金管理（仅查询接口）
- 多个 API 实例的协同

### 8.2 不支持 [D]

- Windows 平台
- 一个实例跨多个市场
- 一个实例同时接 98 + 多个极速柜台
- 一个实例支持多账户（除非使用 FPGA 网关模式）
- 多线程调用同一个 API 实例（用户应自行加锁）[A — 推断自"单线程业务调用"假设]
