## 2. 项目背景与目标

### 2.1 业务背景

券商在 FPGA 极速交易场景下，需要支持多客户共享一台 FPGA 设备的部署形态：
- **直连模式**：api 客户端直接连 FPGA 后台（fdm），但每客户独占一条链路
- **网关模式**（fgw）：多 api 客户端通过 fgw 共享 FPGA 设备

fgw 是网关模式的核心组件，作为业务方 api 与 FPGA 后台 fdm 之间的中间层。

### 2.2 系统目标

fgw 提供统一的 FPGA 柜台网关服务：
- **多 fdm 路由**：动态加载 fdm 列表，按板卡号路由到对应 fdm
- **多客户接入**：一个 fgw 实例可服务多个 api 客户端，每个 api 客户端可承载多客户
- **数据预加载**：启动 + 周期从 db 加载 fdm 列表；板卡上场时加载客户 + 同步证券
- **复杂任务异步化**：数据库加载、证券推送不阻塞消息接收
- **链接可靠**：fdm 链接断开自动重连；fdm 异常时已建立会话保留

### 2.3 系统边界

**包含**：
- 监听 api 客户端 TCP 链接
- 主动连接多个 fdm 后台
- 业务消息路由（上行 + 下行）
- 投资者登录跨链接中转
- 网关登录（fgw 用 log_type=2 向 fdm 发起的登录）
- 板卡状态/客户/证券三类数据加载
- 证券信息分批推送
- 链接建立与关闭处理

**不包含**：
- 业务策略（风控、撤单算法等）
- 行情数据接入
- fdm / FPGA 核心交易逻辑
- 数据库本身的维护
- 监控 / 告警平台对接

## 4. 业务场景

### 4.1 核心场景清单

#### 场景 1：业务上行（核心 — 热路径）

- **输入**：api 发业务消息（订单 `G1_MSG_ORDER_REQ` 1001 / 撤单 `G1_MSG_CANCEL_REQ` 1002）；消息头含 `board_no`
- **处理**：读消息头 `board_no` → 按板卡路由到对应 fdm
- **输出**：消息到达 fdm
- **关键约束**：延迟 < 100us；**绝不能阻塞消息接收**
- **角色**：程序化交易者（api 业务方）
- **频率**：高（5000 笔/秒峰值）

#### 场景 2：业务下行（核心 — 热路径）

- **输入**：fdm 发异步回报（委托回报 2001 / 成交回报 2002 / 撤单响应 2003）；消息头含 `(board_no, session_id)`
- **处理**：读消息头 → 找到该 (板卡, 会话) 对应的 api 接收方 → 透传
- **输出**：消息到达 api 链接
- **关键约束**：延迟 < 100us；找不到接收方则**丢弃 + 日志**（best-effort）
- **角色**：fdm 后台 → fgw → api
- **频率**：高（与上行对称）

#### 场景 3：投资者登录（核心 — 跨链接协作）

- **输入**：api 发登录消息（`G1_MSG_LOGIN_REQ` 1005）；消息头 `board_no=0`，body 含 agwuser 账户（fund_account_id、branch_id 等）
- **处理**：
  - **上行侧**：解析 body 识别 agwuser 账户 → 查客户信息得到 (板卡号, 用户标识) → 补全消息头（含板卡号、用户标识、关联标识） → 转发 fdm
  - **下行侧**：fdm 应答到达 → 用应答带回的关联标识找到原 api 接收方 → 建立 agwuser 与 fdm 会话的关联 → 透传 api
- **输出**：api 完成登录；agwuser 与 fdm 会话的关联建立
- **关键约束**：**跨链接协作**（上行与下行分别在不同 fdm 链接上）；中转瞬时（一发一收）
- **角色**：程序化交易者
- **频率**：中（登录事件，约 1000 峰值）

#### 场景 4：网关登录（核心 — fgw 自身登录）⭐ 新增

- **输入**：fgw 自身需要向 fdm 证明身份（log_type=2）
- **触发时机**：
  - fgw 启动后对每个"应工作"的板卡执行一次
  - fdm 链接断开重连成功后重新执行
- **处理**：fgw 向 fdm 发送 log_type=2 登录请求；fdm 应答确认后 fgw 才能在该板卡上转发业务
- **输出**：fgw 与该 fdm 板卡的"网关登录态"建立
- **关键约束**：未完成网关登录的板卡 → api 业务上行到达时不可路由（应回 `G1_MSG_GW_REJ`）
- **角色**：fgw 自身
- **频率**：低（启动 1 次 + fdm 重连 1 次）

#### 场景 5：板卡数据加载（核心 — 后台异步）

- **输入**：db 板卡状态（`t_fpgastatus` 表）
- **处理**：
  - 启动 + 周期（30s）从 db 加载板卡状态
  - 当某板卡"上场完成"时，加载该板卡的客户（从 db）+ 同步该板卡的证券信息（**从某个特定 fdm 板卡**同步）
- **输出**：内存中该板卡的客户列表和证券信息**可对外服务**
- **关键约束**：
  - 启动期可阻塞；周期加载**不能阻塞**消息接收
  - 证券信息**不来自 db**，来自某个特定 fdm 板卡（"写入者"板卡同步）
  - 多板卡共享同一份证券信息（"全局只有一份"）
- **角色**：fgw 自身（后台）
- **频率**：低（启动 1 次 + 周期 30s）

#### 场景 6：证券推送（核心 — 后台异步）

- **输入**：api 发 `G1_MSG_SEC_INFO_REQ` (1004)
- **处理**：构造推送任务 → 分批发送证券信息（每批 100 条 + 批间让出资源）
- **输出**：api 收到全量证券信息（`G1_MSG_SEC_INFO_ANS` 2005）
- **关键约束**：
  - 每批发送 < 10ms；推送**不阻塞**消息接收
  - 多 api 并发请求互不干扰
- **角色**：程序化交易者
- **频率**：低（按需触发）

#### 场景 7：链接建立（核心）⭐ 新增

##### 7.1 api 链接建立

- **输入**：api 客户端 TCP 连接到 fgw
- **处理**：
  - fgw 接受连接 → 为该链接分配唯一标识（**fgw 内部分配**，全实例内唯一）
  - 建立链接对象（保存标识与底层 fd 关联）
  - 链接进入"待登录"状态
- **输出**：api 链接建立，可接收业务消息
- **关键约束**：分配标识时必须保证全实例内唯一；不阻塞其他已建立链接
- **角色**：api 客户端
- **频率**：中（连接事件，约 1000 峰值）

##### 7.2 fdm 链接建立

- **输入**：fgw 主动 TCP 连接到 fdm（按板卡一对一）
- **处理**：
  - fgw 对每个"应工作"板卡执行一次主动连接
  - 连接成功 → 触发场景 4 网关登录
  - 连接失败 → 进入重连定时
- **输出**：fdm 链接建立，可转发业务
- **关键约束**：每个板卡一个 fdm 链接（1:1）；fdm 链接断开**复用**已有板卡占位（不新建板卡对象）
- **角色**：fgw 自身
- **频率**：低（启动 + 重连）

#### 场景 8：链接关闭（核心）⭐ 新增

##### 8.1 api 链接关闭

- **输入**：检测到 api 链接断开（TCP read 返回 0 或 error）
- **处理**：
  - 移除该链接的标识索引
  - 通知与该链接关联的 agwuser 解除链路绑定（**agwuser 与 fdm 会话本身不销毁**）
- **输出**：api 链接资源释放
- **关键约束**：
  - **agwuser 不销毁**（重连 api 时可复用同一个 agwuser）
  - **fdm 会话不销毁**（fdm 持久化，会话跨 fdm 重启有效）
- **角色**：api 客户端
- **频率**：中（断链事件）

##### 8.2 fdm 链接关闭

- **输入**：检测到 fdm 链接断开
- **处理**：
  - 标记该板卡的 fdm 链接为"重连中"
  - **保留板卡对象和 fdm 链接占位**（不新建对象、不替换）
  - 启动重连定时
  - 重连成功 → 重新执行场景 4 网关登录
  - 失败 → 退避重试
- **输出**：板卡对象持续存在，fdm 链接恢复后继续工作
- **关键约束**：
  - 板卡对象**常驻**（重连不替换）
  - 期间该板卡业务不可达；其他板卡不受影响
- **角色**：fgw 自身
- **频率**：低（断链事件）

### 4.2 辅助场景

| 场景 | 描述 |
|---|---|
| **OFFLINE_PUSH** | fdm 推 (board_no, user_id) → 找到该客户的所有 agwuser → 通知 api 客户下线 |
| **心跳** | api 发 `HEART_REQ` → fgw 自答 `HEART_ANS`，不路由 |
| **启动** | 读配置 → 加载板卡数据 → 启动后台任务 → 监听 api |
| **关闭** | 停接收新 api → 关闭所有链接 → 停止后台任务 → 释放内存 |

## 6. 实体关系

| 实体 A | 关系 | 实体 B | 客观理由 |
|---|---|---|---|
| Board | 1:1 | FdmLink | 一个板卡一个物理端口（硬件约束）|
| Board | 1:N | Customer | 板卡下所有客户（物理包含关系）|
| Customer | N:1 | Board | 客户所属板卡 |
| Customer | 1:N | AgwUser | 一个客户可有多个 agwuser（不同业务身份）|
| AgwUser | 1:1 | ApiLink | 一个 agwuser 对应一个 api 链接（账户与通道绑定）|
| AgwUser | 1:N | FdmSession | 一个 agwuser 跨多个 fdm 板卡 |
| FdmSession | N:1 | Board | session 属于某个 fdm board |
| FdmSession | N:1 | AgwUser | session 属于某个 agwuser |
| ApiLink | 0:1 | AgwUser | api 链接 accept 时无 AgwUser，登录后建立 1:1 |
| Security | 独立 | - | 全局唯一（"全局只有一份"），多 Board 共享 |

## 7. 实体生命周期

| 实体 | 创建时机 | 销毁时机 | 拥有者 | 所有权可转移？ |
|---|---|---|---|---|
| Board | fgw 启动时 db 加载 | fgw 进程退出（**常驻**）| fgw 进程 | 否 |
| FdmLink | Board 创建时（值对象）| fgw 进程退出 | Board | 否（**重连不新建实例**）|
| Customer | 板卡"上场完成"时加载 | 板卡重载时重置 | Board | 否 |
| Security | fgw 启动时同步 | **永不销毁** | fgw 进程 | 否 |
| AgwUser | 首次登录应答到达 | **永不销毁** | fgw 进程 | 否（api 关闭只解引用）|
| FdmSession | fdm 应答到达 | **永不销毁**（fdm 持久化）| fdm 后台 | 否 |
| ApiLink | accept 时 | close 时 | fgw | 否 |

**关键行为**：
- **FdmLink 重连不创建新实例**（Board 持有的值对象身份不变）
- **AgwUser 永不销毁**（api 关闭只解引用 ApiLink 字段；重连时复用）
- **FdmSession 永不销毁**（fdm 持久化 session_id，fdm 重启后 session_id 不变）

## 8. 关键标识的语义

| 标识 | 所属实体 | 分配者 | 稳定性 | 唯一性范围 | 跨重启？ |
|---|---|---|---|---|---|
| 板卡号 (board_no) | Board | db | 稳定 | 全局 | 不变 |
| 用户标识 (user_id) | Customer | fpga 分配 | 稳定 | 板内（**0 连续**）| 不变 |
| 证券索引 (sec_index) | Security | 特定 fdm 板卡 | 稳定 | 全局（**0 连续**）| 不变（写入者板卡持久）|
| agwuser 账户名 | AgwUser | **api 登录传入** | 稳定 | 全局 | 不变 |
| 会话标识 (session_id) | FdmSession | **fdm 分配** | **持久化** | fdm board 内 | **不变**（fdm 重启也不变）|
| api 链接标识 | ApiLink | fgw 分配 | 稳定 | fgw 实例内 | 随 fgw 重启重置 |
| fd | ApiLink | OS 分配 | 不稳定 | 进程内 | 可能复用 |
| 客户键 (cust_key) | Customer | 业务身份（branch+fund 复合）| 稳定 | 全局 | 不变 |

**关键**：
- **会话标识跨 fdm 重启不变**（fdm 持久化）→ FdmSession 在 fgw 内可长期保留
- **agwuser 账户名由 api 传入**（不是 fdm 分配）→ AgwUser 的"源"是业务方
- **证券索引全局 0 连续**（写入者板卡持久）→ 多个 Board 共享同一份 Security
- **用户标识板内 0 连续** → 该板卡客户可按用户标识直接定位

## 9. 反向引用需求（业务可达性）

> **业务需求**：系统必须能从 X 找到 Y。**怎么实现**（用 hash、链表、数组）由架构决定。

| 业务场景 | 查找目标 | 查找依据 | 更新时机 |
|---|---|---|---|
| OFFLINE_PUSH 路由 | 该客户的所有 agwuser（链路集合）| 客户身份 (board + user) | 登录成功加 / api 关闭保留（agwuser 不销毁）|
| 业务下行路由 | 接收方 api 链接 | (板卡, 会话) | fdm 应答建立后保留（fdm 持久化）|
| 登录应答回找 | 接收方 api 链接 | api 链接标识 | 链接建立时加入（永久索引）|

**关键**：
- 这些查找需求**必须在需求中识别**，不能在架构设计时临时发现（会导致设计返工）
- 上行场景"按板卡找 fdm" 由 Board 1:1 FdmLink 关系直接满足，不需额外查找

## 10. 协议层细节（g1 协议）

**g1 协议字段分类**：

| 字段 | 分类 | 含义 | 用途 | 关联 key？ |
|---|---|---|---|---|
| msg_id | 协议控制 | 消息号 | 路由分发 | 否 |
| msg_len | 协议控制 | 包体长度 | 解析 | 否 |
| version | 协议控制 | 版本号 | 协议兼容 | 否 |
| **board_no** | 路由 | 板卡号 | **业务上行路由**（api → fdm）| 是（路由 key）|
| user_id | 协议控制 | 用户索引 | fpga 内部 | 否 |
| **session_id** | 协议控制 | 会话 id | **业务下行路由**（fdm → api）| 是（fdm 分配，**fdm 重启不变**）|
| fund_account_id | 业务身份 | 资金账号 | 登录中转（识别客户）| 否 |
| branch_id | 业务身份 | 分支机构 | 登录中转 | 否 |
| cust_id | 业务身份 | 客户号 | 业务身份 | 否 |
| holder_acc | 业务身份 | 股东账号 | 业务身份 | 否 |
| **api 链接标识** | 关联 key | fgw 给 api 链接分配的内部标识 | fgw→fdm 登录中转 + fdm 应答反查 api 链接 | **是**（fgw 分配，fdm 应答带回）|
| market_type | 业务身份 | 市场 | 业务身份 | 否 |

**关联 key 语义**：
- **api 链接标识**（fgw 内部分配）：fgw 给每个 api 链接分配的唯一标识
- 登录请求时：fgw 将其写入登录消息的关联字段，发送给 fdm
- 登录应答时：fdm 原样写入应答的关联字段带回
- fgw 用带回的标识找到对应的 api 链接

**业务身份字段**：
- `fund_account_id` / `branch_id` / `cust_id` / `holder_acc` 用于识别客户身份
- 登录请求 body 中必须包含这些字段
- fgw 通过 (fund_account_id, branch_id) 复合 key 识别客户

**路由字段**：
- 业务上行：`board_no` 路由到对应 fdm
- 业务下行：`(board_no, session_id)` 路由到对应 api 链接

## 11. 数据加载语义

| 数据 | 来源 | 加载时机 | 可服务时机（业务可观察）| 业务可接受延迟 |
|---|---|---|---|---|
| fdm 列表 | db（`t_fpgastatus`）| 启动 + 周期 30s | 该板卡状态被加载 | 启动可阻塞；周期不能阻塞 |
| 客户信息 | db（`fdm_board_user`）| 板卡"上场完成"时懒加载 | 该板卡的客户列表对外可查 | 启动可阻塞 |
| **证券信息** | **特定 fdm 板卡同步**（**非 db**）| 板卡"上场完成"时同步 | 该板卡的证券信息对外可查 | 启动可阻塞 |
| 板卡内客户 | db（按板卡）| 板卡新增时 | 该板卡客户列表填充完成 | 启动可阻塞 |

**关键**：
- **证券信息不来自 db**，来自某个特定 fdm 板卡（"写入者"板卡同步）
- 多 Board 共享同一份证券信息（全局只有一份）
- "可服务时机"指**业务上可观察**的状态（如客户列表可查、证券信息可查），**怎么实现**（用什么标志位、什么原子变量）由架构决定

**反例澄清**（避免需求偏差）：
- ~~"证券信息从 db 加载"~~ 错：实际从特定 fdm 板卡同步
- ~~"agwuser 标识由 fdm 分配"~~ 错：实际由 api 登录传入
- ~~"会话标识跨 fdm 重启变化"~~ 错：实际 fdm 持久化不变
- ~~"api 关闭销毁 AgwUser"~~ 错：实际 AgwUser 永不销毁，只解引用

## 12. 业务不变量（仅业务层面 — 设计不变量归 ARCHITECTURE.md）

| # | 不变量 | 说明 |
|---|---|---|
| I1 | 路由必须快 | 业务上行 / 下行路由延迟 < 100us |
| I2 | 会话跨 fdm 重启有效 | fdm 重启后，会话标识不变，已建立会话保留 |
| I3 | 板卡与 fdm 链接 1:1 | 板卡对象常驻，fdm 链接断开复用同板卡 |
| I4 | agwuser 永不销毁 | api 关闭只解引用，agwuser 跨关闭保留 |
| I5 | 多板卡共享一份证券信息 | 写入者板卡持久，全局 0 连续 |
| I6 | 路由失败 best-effort | 业务下行找不到接收方 → 丢弃 + 日志（不重试、不阻塞）|
| I7 | 路由失败要明确回执 | 业务上行找不到 fdm → 回 `G1_MSG_GW_REJ` |
| I8 | 数据加载不阻塞消息接收 | 周期加载 / 证券推送异步进行 |
| I9 | api 关闭不影响 fdm 会话 | fdm 会话与 api 链接生命周期解耦 |

## 13. 错误处理业务语义（新增）

| 错误情形 | 业务行为 | 备注 |
|---|---|---|
| api 发登录但客户身份未在 fgw 注册 | 拒绝登录请求 + 透传失败应答 | 业务可观察：客户无法登录 |
| api 发业务上行但板卡未加载 | 回 `G1_MSG_GW_REJ`（路由拒绝）| 业务可观察：业务被拒 |
| api 发业务上行但网关登录未完成 | 回 `G1_MSG_GW_REJ` | 业务可观察：业务被拒 |
| fdm 应答但找不到 api 接收方 | 丢弃 + 日志 | 业务可观察：丢单（best-effort）|
| fdm 链接断开 | 标记重连中 + 重连；其他板卡不受影响 | 业务可观察：该板卡业务暂时不可达 |
| api 客户端异常关闭 | 解引用 agwuser 与 api 链接的关联；agwuser 保留 | 业务可观察：会话保留，重连可恢复 |
| db 加载失败（周期）| 跳过本次加载 + 记日志；下个周期重试 | 业务可观察：数据稍陈旧但不阻塞 |
| db 加载失败（启动）| fgw 启动失败 + 退出 | 业务可观察：fgw 不可用 |
| 证券推送中途错误 | 跳过错误批次 + 继续后续 | 业务可观察：可能少部分证券缺失 |

## 14. 假设与依赖

### 14.1 外部依赖

- **fdm 后台**：由 fdm 厂商提供，遵循 g1 协议
- **FPGA 交易核心**：由 fdm 厂商提供
- **数据库**：存储 fdm 列表 / 客户；提供 SQL 查询
- **common 基础库**（`~/src/common`）：异步 IO、队列、哈希、线程、重连控制
- **gone 项目 include**：g1 协议定义
- **Linux**：epoll / timerfd
- **C++17**

### 14.2 业务假设

- api 端使用 gone/api C++ 库
- fdm 端已部署 + 数据库已就绪
- 数据库读取频率不高（分钟级），不需要专门的查询优化
- 业务方理解 g1 协议 + TCP 异步 IO 模型

## 15. 验收标准

### 15.1 功能验收

- [ ] fgw 启动后监听指定 IP:PORT
- [ ] 数据库加载 fdm 列表正确（按规则过滤）
- [ ] 数据库加载客户信息正确（按板卡号关联）
- [ ] 证券信息从特定 fdm 同步（**非 db**）
- [ ] fgw 主动连接所有"应工作"的 fdm 并完成网关登录
- [ ] api 客户端能连接 fgw 并完成投资者登录
- [ ] 上行业务消息按 `board_no` 路由到正确 fdm
- [ ] fdm 异步回报按 `(board_no, session_id)` 路由回正确 api 链接
- [ ] 路由失败返回 `G1_MSG_GW_REJ`
- [ ] 找不到 api 链接时 fdm 回报被丢弃
- [ ] 证券信息全量分批推送正常
- [ ] fdm 断开自动重连（FdmLink 不新建实例）
- [ ] api 链接关闭保留 agwuser 与 fdm 会话
- [ ] 板卡 status='1' 触发客户 + 证券加载
- [ ] fgw 进程异常退出无资源泄漏

### 15.2 性能验收

- [ ] 业务路由转发延迟 < 100us
- [ ] 并发委托 ≥ 5000 笔/秒
- [ ] 并发 api 链接 ≥ 1000
- [ ] 实例启动 < 10 秒
- [ ] 实例关闭 < 5 秒

### 15.3 可靠性验收

- [ ] fdm 单点故障不影响其他 fdm 路由
- [ ] 数据库临时不可用 fgw 不崩溃
- [ ] 路由失败不阻塞消息接收
- [ ] 证券推送中途错误不阻塞后续推送
- [ ] fdm 重启后会话标识不变（fgw 中 FdmSession 保留）

## 17. 业务方验收问题（新增）

> **目的**：让业务方在签收需求前，自行回答以下问题。如果答不出来或答错，说明需求描述不清。

1. 业务上行延迟 < 100us 是设计指标还是业务硬约束？（答：业务硬约束）
2. fdm 重启后 fgw 中的 fdm 会话是否仍然有效？（答：有效，会话标识不变）
3. api 客户端断线后其 agwuser 是否销毁？（答：不销毁，重连可复用）
4. 证券信息从 db 加载还是从某个 fdm 同步？（答：从特定 fdm 同步）
5. fdm 链接断开后板卡对象是否重建？（答：不重建，复用原板卡 + fdm 链接占位）
6. 业务下行找不到接收方时系统如何处理？（答：丢弃 + 日志，不重试不阻塞）
7. 板卡"上场完成"后 fgw 还需要从 db 加载什么数据？（答：客户；证券从特定 fdm 同步）
8. fgw 与 fdm 之间的登录和 api 与 fdm 之间的登录是同一个登录吗？（答：不是，fgw 用 log_type=2 网关登录，api 用 log_type=1 投资者登录）
9. 多 api 客户端能共享同一个 agwuser 吗？（答：不能，AgwUser 1:1 ApiLink）
10. 关闭 fgw 时已经建立的 agwuser 与 fdm 会话会持久化吗？（答：不会，fgw 不持久化）
