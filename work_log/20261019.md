## 任务：定位并修复 GW 性能测试心跳超时断链（回归根因）
**时间**：01:00-01:18

### 工作内容
1. CPU 绑核隔离（tgw_simulator→0,1,2；上海FTE→3,4；深圳FTE→5,6；counter98→7；gone_counter→8）后，GW 5000/2000 TPS 仍失败（-35/-22），排除 CPU 竞争因素。
2. 逐层排查，定位到**代码回归根因**：
   - `aio_tcp.h` 第189行 `// heart.on_msg()` 被注释，新增 `on_com_msg()` 封装（第304行）。
   - **`on_com_msg()` 定义了但从未被调用**（dead code）。
   - GW 的 `deal_recv_msg`（gw_counter_direct.cpp）只对心跳消息(`kPktNewHeartBeat`)调 `deal_heart_msg_ans`，业务消息未调 `on_com_msg()`。
   - `heart.on_msg()` 只更新 `last_heart`（活性时钟），业务消息不保活 → FTE 心跳中断时 15 秒后断链（`tin×3=5×3`）。
3. **修复**：在 `aio_socket_link.h` 的 `deal_msg` 中调用 `pch->on_com_msg()`，业务消息到达时刷新心跳活性。

### 结论
- 修复后重新编译，GW 5000 TPS：**49674 全部成功，0 失败**，功能 5/5 通过，无断链。
- GOne 10000 TPS（修复后）：**98793 全部成功，0 失败**，无副作用。
- 修复无副作用（on_com_msg 仅更新 last_heart）。

### 经验教训
1. **回归根因**：其他主机更新代码时，把 `heart.on_msg()` 注释并封装成 `on_com_msg()`，但未在业务消息路径手动调用，导致业务消息不保活、心跳超时断链。**这是典型的"重构引入 dead code + 未接线"回归**。
2. **排查方法论**：性能测试断链时，先排除环境（CPU 竞争）→ 对比 GOne/GW（交叉验证）→ 检查心跳保活逻辑（on_com_msg 是否被调用）→ 定位代码回归。
3. **心跳机制**：`heart.on_msg()` 只更新 last_heart，无副作用；业务消息须在 `deal_msg` 回调手动调 `on_com_msg()`（aio_tcp 内被注释）。文档（架构范式.md/05-business-recipes.md/06-pitfalls-index.md N4）已明确此约定。
4. **修复位置**：`aio_socket_link.h` 的 `deal_msg`（所有用 aio_socket_link 的柜台通用），统一在业务消息到达时保活。
