### 一、把 dse "exit=157" 的根因挖到底（本轮最大收获）

1. **先排除符号因素**：把 ATP 现构建的 4 个运行库同步进 `dse_deps`
   （`libabf_util` 92.6MB / `libbiz_msg` 39.5MB / `libabf_tech` 5.9MB / `libmsg_proto` 2.9MB，
   原 4 个旧库备份到 `dse_deps.bak_20261112/`），随后**去掉**上一轮为放行链接加的
   `-DCMAKE_EXE_LINKER_FLAGS=-Wl,--unresolved-symbols=ignore-in-shared-libs` 重配，
   `rm -f dse/dse && make dse` 干净重链成功；`ldd -r` 未定义/缺失符号 **= 0**
   （旧 `dse_deps/libabf_util.so` 缺 26 个 `Pkt*` vtable 符号，新库全部有定义）。
2. **157 仍在**：dse 日志固定 7 行，末行 `DseEngineMDProcess Init`（static-init 期间），
   之后退出。用 `--log-to-console` 退出码变 170，说明**退出码依赖 argv**。
3. **反汇编定位**：`nm -S dse | grep ' T main'` → `main` 仅 0x7f 字节；
   `objdump` 显示它在做 `info_compiler[argc] + info_platform[argc] + info_version[argc] + ...`
   求和 —— 这是 **CMake 的 `CMakeCXXCompilerId.cpp` 生成的 main**，不是 DSE 的 main。
4. **根因**：`dse/CMakeLists.txt` 的 `file(GLOB_RECURSE "./*.cpp")` 把残留
   `dse/build/CMakeFiles/3.19*/CompilerIdCXX/CMakeCXXCompilerId.cpp` 收进源文件列表；
   该文件的 `main` 链进 exe 后顶掉了 `libaaf.so` 提供的框架 `main`（DSE 本应不定义 main）。
   因此 dse 只跑完静态初始化（所以有 `QE start info` 日志）就以随机码退出，应用 main 从不执行。
5. **修复**：`list(FILTER SRC_FILES EXCLUDE REGEX "/build(_cmake)?/")`（原先只排除 `build_cmake/`）。
   重链后 `nm -D dse | grep -w main` 为 `U main`（运行时由 libaaf.so 提供）；
   再启动 dse：出现 `dse::DataSyncEngine SetAmiAppOption/OnAmiAppOption`，进程常驻，
   监听 28444/28445/20592/26512。

### 六、经验教训

1. **"进程退出但无日志"先怀疑链接产物本身**：反汇编/`nm` 看 `main` 是否来自你的源码，
   再谈初始化流程；本次两天卡点的根因是一个残留构建目录被 `GLOB_RECURSE` 收进去。
2. **`GLOB_RECURSE` 一定要排除构建目录**（`build/`、`build_*`），否则 CMake 自检源会混入目标。
3. **报文长度类问题要用"结构尺寸实测"对账**：容器里编译最小 TU 打印 `sizeof`，
   比逐字段数偏移快且准；本次 106 vs 108 就是缺 1 个 `uint16`。
4. **测试预期值必须有代码/实测依据**：`order_status=10/2`、`rtn_type='1'` 都是先找到
   FTE/ATP 的枚举定义再改，避免"改预期凑绿"。
5. **分支运行目录要显式覆写**：`env.sh` 的 `RUN_DIR` 是 `${WORK_ROOT}/run`，
   在 `run_<branch>` 部署下必须覆写，否则拉起的是别的目录的上场库。
