### 经验教训
1. **现象**：所有 `pwsh` 命令报 `SetNamedSecurityInfoW failed (Win32 5): grantWrite`。**根因**：工作区目录 ACL 缺 `WRITE_OWNER`（只有 `WRITE_DAC`），沙箱无法为自己授权。**解法**：用 `diagnose-windows-sandbox-acl` 单命令诊断+修复（先备份 DACL），修复后原操作恢复正常；不要手工改 ACL。
2. **现象**：`review_prepare.sh` 用 w64devkit 的 bash 跑，报 `line 63: syntax error: unexpected "("`（exit=2）。**根因**：w64devkit 的 bash 不支持数组，第 63 行 `FILES=()` 无法解析；其 `date` 也无 `-d`。**解法**：固定用 Git bash（`C:\Program Files\Git\bin\bash.exe`）运行，实测正常聚合；**踩坑提醒：不要凭"工具在 PATH 里"就假定语义兼容，先跑一次看真实产物**。
3. **现象**：`task_rule.md` §5 要求 docker otc + CMake 编译部署，本机执行必失败。**根因**：规则源自 Linux 主机，Windows 工作区无 docker/WSL。**解法**：把"环境事实"写进知识库（`体系总览` §7.1 + `Prompt.md` §九），按任务类型分流，避免在不可编译的环境里硬试。
4. **现象**：知识库目录列 §31 但正文缺失、规则引用的 `study/knowledge_base/` 与 `11_工程纪律.md` 不存在。**根因**：多次跨主机迁移/融合后索引与实体脱节，且无人核对。**解法**：本次建立"引用 vs 实体"核对习惯并写入缺口清单，后续沉淀时先核对再引用。
5. **方法论**：掌握一套体系的高效方式是"**读规范 → 实测链路 → 写元层文档 → 反向核对缺口**"，比只读文档更能发现失效引用（本次 8 项缺口全部来自实测与核对）。
